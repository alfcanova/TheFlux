Para a SimdStdLib, o foco central da biblioteca na TheFlux é atuar como a camada de aceleração de hardware de mais baixo nível para dados homogêneos contíguos. Ela não deve ser um roteador genérico, mas sim fornecer algoritmos e primitivos vetorizados dedicados que tirem proveito direto dos registradores de vetor de 128, 256 ou 512 bits dos processadores modernos (como SSE, AVX2, AVX-512 no desktop e a extensão oficial SIMD no WebAssembly).Como a TheFlux possui o par LinAlgStdLib (Álgebra Linear) e StatStdLib (Estatística) rodando loops iterativos, a SimdStdLib agirá como o motor oculto ou explícito para paralelizar essas operações a nível de instrução (dataflow puro de hardware).
🎯 1. Funções Necessárias / EssenciaisAs funções de núcleo que operam sobre conjuntos contíguos de memória, processando múltiplos elementos em um único ciclo de clock. Os tipos de dados devem refletir precisões multi-bit nativas da linguagem (f64, f32, i64, i32).simdVectorAddF32 (as list of data: a, as list of data: b) as list of dataObjetivo: Realiza a soma de dois vetores elemento a elemento. Se o processador possuir AVX2, ele processará 8 floats de 32 bits de uma única vez em vez de iterar elemento por elemento.simdVectorMulF32 (as list of data: a, as list of data: b) as list of dataObjetivo: Multiplicação de dois vetores elemento a elemento (Hadamard product), gerando a base para o produto escalar de alta velocidade.simdDotProductF32 (as list of data: a, as list of data: b) as float32Objetivo: Algoritmo vetorizado dedicado do produto escalar. Ele carrega os blocos na CPU, faz a multiplicação em massa de registradores paralelos e realiza uma adição horizontal final para cuspir o escalar.simdMatrixMul2DF32 (as map: lhs, as map: rhs) as mapObjetivo: Multiplicação de matrizes 2D utilizando blocos vetorizados SIMD (re-arranjando o acesso à memória para formato contíguo), acelerando drasticamente o motor do LinAlgStdLib.🧩 2. Funções AcessóriasFunções de suporte voltadas para mascaramento lógico, alinhamento físico de memória e restrições de hardware controladas por contratos.simdIsAligned (as data: pointer, as int64: bytes) as boolObjetivo: Verifica se o endereço inicial da memória está alinhado fisicamente (ex: alinhamento de 16, 32 ou 64 bytes), o que é obrigatório para evitar falhas de segmentação em instruções SIMD cruas no hardware.simdVectorClampF32 (as list of data: a, as float32: min_v, as float32: max_v) as list of dataObjetivo: Restringe simultaneamente todos os valores de um vetor entre limites mínimos e máximos utilizando registradores de hardware (essencial para o motor do GfxStdLib).simdSelectF32 (as list of data: mask, as list of data: a, as list of data: b) as list of dataObjetivo: Operação de máscara lógica vetorial (executa condicionais em hardware sem ramificações/saltos if, aplicando o estado verdadeiro ou falso em múltiplos dados de uma vez).🏗️ 3. Sugestão de Implementação no Cenário MultiendComo o seu compilador em Python gerencia geradores de código radicalmente opostos, a SimdStdLib extrairá o máximo de cada plataforma:A. No Interpretador (Python)Para manter os seus testes canônicos passando idênticos, o interpretador em Python lerá o nó da AST da SimdStdLib e traduzirá a execução roteando os dados diretamente para operações vetorizadas do NumPy (que é escrito em C estruturado em SIMD). Se o usuário rodar simdDotProductF32, o Python executará em milissegundos usando np.dot().B. Na LLVM IR + Clang (.exe nativo)Aqui a sua linguagem alcançará o desempenho de C estruturado. A LLVM possui suporte nativo absoluto para vetores através de tipos literais de tamanho fixo:A Engrenagem: O seu compilador Python gerará variáveis na LLVM IR utilizando a sintaxe de vetores fixos, como <4 x float> (um registrador de 128 bits guardando 4 floats) ou <8 x float> (256 bits guardando 8 floats).As Instruções: Operações matemáticas comuns virarão instruções SIMD nativas da LLVM como fadd <4 x float> ou fmul <4 x float>. O Clang lerá essa IR e gerará as instruções de assembly reais do processador do usuário (como VADDPS do AVX).C. No WebAssembly (wasm / wat)O WebAssembly possui uma especificação oficial consolidada e performática para vetores chamada WASM SIMD.A Engrenagem: O seu gerador de texto WAT traduzirá as operações vetoriais utilizando o tipo de hardware v128 (um registrador de 128 bits do WASM).As Instruções: A multiplicação e soma de blocos serão traduzidas diretamente para instruções cruas de WAT como f32x4.mul, f32x4.add e adições horizontais. Isso fará com que o código da TheFlux rode em velocidade nativa direto na sandbox de qualquer navegador web.D. O Casamento Rígido com Ownership (move / borrow)Operações de checagem física de hardware (como simdIsAligned) rodam estritamente via borrow, blindando a entrada de um nó antes do processamento pesado.Como processar vetores em hardware exige buffers contíguos limpos, as funções matemáticas consumirão os vetores de entrada como move. A AST em Python invalida imediatamente os arrays antigos na CPU para evitar duplicações desnecessárias na memória RAM, enquanto o novo vetor transformado pelo registrador SIMD é injetado na esteira linear e liberado pelo canal emit(nice, result_vector, "ok").
