Para a LowLevelStdLib, o design arquitetural deve focar na capacidade da TheFlux de interagir diretamente com a memória crua, registradores físicos de hardware (MMIO) e manipulação cirúrgica de bits. Como a sua linguagem gerencia recursos estaticamente na AST por meio de Ownership (move/borrow) e não possui Garbage Collector, esta biblioteca fornece as primitivas para programação de sistemas, drivers e protocolos binários de rede com segurança garantida por contratos.Diferente das abstrações de alto nível, aqui trabalhamos com tamanhos de dados exatos do hardware: Bits, Bytes (8 bits), HWords (Half-Words / 16 bits), Words (32 bits) e DWords (Double Words / 64 bits).🎯 1. Funções Necessárias / EssenciaisAs funções fundamentais de manipulação e transferência de dados diretamente na memória e registradores de tamanho fixo.lowPeekByte (as int64: address) as uint8 / lowPokeByte (as int64: address, as uint8: value) as boolObjetivo: Lê (peek) ou escreve (poke) um byte bruto diretamente em um endereço de memória física. Possui variações idênticas para todos os tamanhos: HWord (16 bits), Word (32 bits) e DWord (64 bits).lowBitAnd (as int64: value, as int64: mask) as int64 / lowBitOr (as int64: value, as int64: mask) as int64Objetivo: Executa operações lógicas bit a bit (bitwise), incluindo Xor e Not. Essencial para ligar, desligar ou mascarar flags de registradores.lowShiftLeft (as int64: value, as int64: bits) as int64 / lowShiftRight (as int64: value, as int64: bits) as int64Objetivo: Desloca os bits para a esquerda (shl) ou direita aritmética/lógica (shr/ushr).lowMemCopy (as int64: src_address, as int64: dst_address, as int64: num_bytes) as boolObjetivo: Copia blocos de memória brutos de forma contígua e ultra-rápida (o equivalente ao memcpy de baixo nível).🧩 2. Funções AcessóriasFunções de conveniência focadas em alinhamento de ponteiros, endianness (ordem dos bytes) e segurança controlada por contratos.lowIsAligned (as int64: address, as int64: alignment_bytes) as boolObjetivo: Verifica se um endereço está perfeitamente alinhado na memória (múltiplo de 4, 8, 16 bytes), o que é obrigatório para alimentar a sua SimdStdLib sem quebrar o hardware.lowByteSwap16 (as uint16: v) as uint16 / lowByteSwap32 (as uint32: v) as uint32 / lowByteSwap64 (as uint64: v) as uint64Objetivo: Inverte a ordem dos bytes (Endianness Conversion). Crucial para a NetStdLib quando é necessário converter dados de Big Endian (rede) para Little Endian (arquitetura x86/ARM local).lowBitCheck (as int64: value, as int64: bit_index) as boolObjetivo: Isola e verifica se um bit específico (1-indexado para humanos na TheFlux) está ativo (1) ou inativo (0).🏗️ 3. Sugestão de Implementação no Cenário MultiendComo esta biblioteca mexe diretamente no silício da máquina, o comportamento dela se ramifica de forma fascinante nos seus backends através do compilador Python:A. No Interpretador (Python)Para que os seus testes canônicos continuem passando de forma idêntica no interpretador sem quebrar o seu sistema de desenvolvimento, você emulará a memória física utilizando um array de bytes brutos (bytearray do Python mapeado na sua AST). Os endereços passados como int64 viram índices desse array virtual, e as leituras/escritas de Words e DWords usam o módulo struct do Python para empacotar os bytes corretamente.B. Na LLVM IR + Clang (.exe nativo)Aqui a biblioteca atinge performance de hardware pura e bruta. O seu gerador de código em Python mapeia as funções da LowLevelStdLib diretamente para ponteiros intrínsecos e instruções fundamentais da LLVM IR:A leitura/escrita de Words vira instruções load i32, i32* e store i32.As operações de bit viram instruções de hardware como and i64, or i64, shl i64 e lshr i64. O Clang gera o binário final compilando isso para instruções de clock único da CPU.C. No WebAssembly (wasm / wat)No navegador, por questões de segurança (Sandbox), o WASM não pode acessar a memória RAM real do computador.A Solução: O seu gerador de texto WAT mapeará todos os endereços de ponteiros de forma relativa para dentro da Linear Memory alocada para o módulo WASM.As Instruções: A leitura e escrita de DWords e Words serão traduzidas diretamente para instruções nativas em WAT como i64.load, i32.load, i64.store, i32.and e i32.shl.D. O Casamento Rígido com Ownership e Contratos (move / borrow)Mexer com baixo nível é perigoso, mas a TheFlux blinda o programador usando contratos:textstep GravarPortaSerial {
      // O contrato impede fisicamente a escrita fora da região de memória mapeada (MMIO)
      contract: address >= 0x40000000 and address <= 0x4000FFFF
      contract: LowLevelStdLib.lowIsAligned(address, 4) // Garante alinhamento de Word
      
      execute: LowLevelStdLib.lowPokeWord(address, borrow valor)
}
Use o código com cuidado.As funções de leitura (lowPeek) operam via borrow, apenas espiando o estado da memória sem destruir o ponteiro.As funções de escrita ou movimentação de blocos em massa (lowMemCopy) operam via move se o ciclo de vida da AST determinar que aquele buffer contíguo de dados foi transferido definitivamente para o controle de um driver ou do nó de rede, liberando o escopo antigo estaticamente.
