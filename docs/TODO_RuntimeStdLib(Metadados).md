Para a RuntimeStdLib, o foco central da biblioteca padrão na TheFlux é fornecer a capacidade de introspecção e controle do próprio motor de execução, agindo de forma complementar à OsStdLib. Enquanto a OsStdLib monitora o hardware externo (como uso de CPU e memória RAM da máquina), a RuntimeStdLib olha para dentro da linguagem, inspecionando o ciclo de vida dos recursos alocados e os metadados gerenciados pela árvore sintática abstrata (AST).Como o gerenciamento de memória da TheFlux é estático e baseado na AST (via Ownership/Move/Borrow), a RuntimeStdLib não gerencia um Garbage Collector, mas fornece as ferramentas definitivas para auditoria de vazamentos de memória, reflexão estática de tipos e ganchos personalizados de pânico para os contratos.🎯 1. Funções Necessárias / EssenciaisAs funções de núcleo que permitem ao programa inspecionar seus próprios tipos, argumentos e gerenciar o comportamento crítico do runtime.runtimeGetTypeName (as data: value) as stringObjetivo: Retorna o nome do tipo exato de qualquer variável ou estrutura em tempo de execução (ex: retornando "int64", "string" ou o nome de uma struct da StructStdLib). Essencial para nós que lidam com dados genéricos.runtimeGetArgs () as list of dataObjetivo: Captura os argumentos brutos de linha de comando passados para o executável no momento da inicialização, retornando-os como uma lista sequencial de strings.runtimeSetPanicHook (as string: agent_name, as string: op_name) as boolObjetivo: Registra uma operação de um agente para interceptar e capturar o momento exato em que um contrato falha. Em vez de apenas derrubar o programa bruscamente, o runtime desvia a execução para essa rotina para salvar um dump de segurança.runtimePanic (as string: message) as boolObjetivo: Aborta a execução do programa imediatamente, disparando o canal de falha global e exibindo a mensagem semântica de erro no console de diagnóstico.🧩 2. Funções AcessóriasFunções utilitárias voltadas para auditoria de escopo, rastreamento de pilha e metadados estruturais.runtimeStackTrace () as list of dataObjetivo: Retorna uma lista de strings contendo a pilha de chamadas (stack trace) atual dos nós de fluxo linear, ideal para a DebugStdLib gerar relatórios precisos de erros.runtimeCompilerVersion () as stringObjetivo: Retorna a versão atual do compilador em Python que gerou aquele binário (útil para auditoria de compatibilidade de builds).runtimeGetStructMetadata (as string: struct_name) as mapObjetivo: Retorna um mapa completo contendo os metadados estáticos de uma estrutura (tamanho total em bytes, lista de campos e flags de mutabilidade), estendendo as capacidades da StructStdLib.🏗️ 3. Sugestão de Implementação no Cenário MultiendA RuntimeStdLib é a biblioteca mais camaleônica da TheFlux, pois ela interage diretamente com as entranhas de cada ambiente mapeado pelo seu compilador em Python:A. No Interpretador (Python)A implementação do agente na fase interpretada consome os metadados que o seu próprio compilador em Python coletou na leitura da AST.runtimeGetTypeName usa o mapeamento do seu dicionário de tipos ou a função nativa type(value).__name__.runtimeGetArgs lê diretamente a lista nativa sys.argv.Os ganchos de pânico usam blocos protegidos de captura de exceções (try/except) criados no motor do interpretador.B. Na LLVM IR + Clang (.exe nativo)Em código binário compilado, os nomes das variáveis e tipos desaparecem e viram apenas endereços de hardware. Para manter a reflexão ativa:A Estratégia: O seu compilador em Python gera e injeta uma tabela estática de strings ocultas (Metadata Table) na LLVM IR durante a compilação do executável.O Despacho: Quando o .exe invoca runtimeGetTypeName, ele consulta o ID numérico do tipo nessa tabela estática e retorna o ponteiro da string correspondente. O runtimePanic é mapeado diretamente para a função nativa de interrupção da biblioteca padrão do C (exit(1) ou rotinas de pânico de hardware via Clang).C. No WebAssembly (wasm / wat)No navegador, o ambiente de isolamento exige pontes com a página hospedeira.A Estratégia: Para capturar os argumentos de inicialização (runtimeGetArgs), o gerador de texto WAT cria um JS Binding (importação externa) que busca os parâmetros passados na inicialização do script no Node.js (process.argv) ou na URL do navegador. O pânico do runtime é mapeado para uma instrução WAT unreachable, que trava o módulo WASM imediatamente e joga o log de erro no console de desenvolvedor do browser.D. O Casamento Rígido com Ownership (move / borrow)As funções de inspeção de metadados e tipos (runtimeGetTypeName, runtimeGetStructMetadata) operam estritamente sob a semântica de borrow. Elas apenas espiam os identificadores e cabeçalhos de dados sem tomar a posse ou alterar as variáveis na esteira de fluxo linear.A leitura de argumentos (runtimeGetArgs) gera uma nova lista na memória linear, transferindo a propriedade total desse recurso para o primeiro nó receptor do pipeline através do canal tradicional emit(nice, args_list, "ok").
