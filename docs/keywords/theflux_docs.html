Controle de Fluxo Condicional

Avalia condições em ordem e executa o bloco correspondente ao primeiro braço cuja condição seja verdadeira.

Sintaxe

Exemplo

      "kw">true  ==> { "kw">print("Verdadeiro") }

match
Keywords

Descricao

Realiza casamento de padrões (pattern matching) sobre uma expressão. O match é uma expressão e retorna o valor produzido pelo primeiro braço cujo padrão corresponda ao valor analisado e cuja guarda (guard), quando presente, seja verdadeira. A sintaxe de desestruturação reutiliza exatamente a mesma forma utilizada na construção de structs e variantes de enum, tornando construção e desconstrução operações simétricas. Para enums, o compilador verifica exaustividade e detecta braços inalcançáveis.

Sintaxe

"kw">match (<expressao>) {

    <padrao> ==> <expressao>

    <padrao> (<expressao_booleana>)
        ==> <expressao>

    ...

}

Pseudocodigo

ESCOLHER(expressao):
    CASO padrao_1: resultado_1
    CASO padrao_2: resultado_2
    PADRAO: resultado_fallback

Usos

Match com literais

Seleciona um braço com base em valores literais.

"kw">match (valor) {

    1 ==> "um"

    2 ==> "dois"

    _ ==> "outro"

}

Match com enum

Desestrutura variantes de enum utilizando a mesma sintaxe empregada durante sua construção.

"kw">match (resposta) {

    Resultado::Ok(
        .valor: valor
    ) ==> valor

    Resultado::Erro(
        .mensagem: mensagem
    ) ==> mensagem

}

Match com struct

Desestrutura structs utilizando exatamente a mesma sintaxe utilizada durante sua construção.

"kw">match (evento) {

    Evento(

        .nome: nome

        .quando: quando

        .contador: contador

    ) ==> contador

}

Match com registro

Desestrutura registros anônimos por nome de campo.

"kw">match (registro) {

    {

        .tipo: "sensor"

        .valor: valor

    } ==> valor

    {

        .tipo: tipo

    } ==> tipo

    _ ==> "desconhecido"

}

Match com guard

Executa o braço apenas quando o padrão corresponde e a condição booleana é verdadeira.

"kw">match (resultado) {

    Resultado::Ok(
        .valor: valor
    ) (valor >= 0) ==> "positivo"

    Resultado::Ok(
        .valor: valor
    ) ==> "negativo"

    Resultado::Erro(
        .mensagem: msg
    ) ==> msg

}

Match aninhado

Permite desestruturar estruturas compostas em um único padrão.

"kw">match (usuario) {

    Usuario::Ativo(

        .pessoa:

            Pessoa(

                .nome: nome

                .idade: idade

            )

    ) ==> nome

    Usuario::Bloqueado(

        .motivo: motivo

    ) ==> motivo

}

Restricoes

  • Match é uma expressão.
  • O match retorna o valor produzido pelo primeiro braço correspondente.
  • Deve existir pelo menos um braço.
  • Os braços são avaliados na ordem em que aparecem.
  • O primeiro padrão correspondente cuja guarda seja verdadeira encerra a avaliação.
  • A guarda é opcional e é escrita como expressão booleana entre parênteses após o padrão.
  • A guarda não é um padrão: um braço precisa de um padrão (braços somente com guarda são erro de parse).
  • Guards são avaliados somente após o padrão correspondente ser satisfeito.
  • Um braço com guarda não cobre incondicionalmente o padrão: variantes/wildcards guardados não tornam o match exaustivo nem marcam braços seguintes como inalcançáveis.
  • O padrão _ corresponde a qualquer valor.
  • Todo campo é obrigatoriamente prefixado por ponto (.) e ocupa uma linha própria; campos são separados por quebra de linha (EOL), nunca por vírgula.
  • Padrões de struct verificam nominalmente o tipo.
  • Padrões de enum verificam nominalmente o enum e a variante.
  • A correspondência dos campos ocorre pelo nome, nunca pela posição.
  • Campos podem ser ignorados utilizando _.
  • A construção e a desestruturação utilizam exatamente a mesma estrutura sintática.
  • Em backends tipados (LLVM, WASM/WAT), todos os braços devem produzir tipos compatíveis.
  • Quando a expressão analisada possuir um tipo enum, o compilador deve verificar a exaustividade do match.
  • Um match é considerado exaustivo quando todas as variantes do enum são cobertas explicitamente ou quando existe um braço wildcard (_).
  • Para structs, o pattern matching é naturalmente exaustivo, pois existe apenas um construtor possível.
  • O compilador deve detectar braços inalcançáveis.
  • Um braço cujo padrão nunca possa ser selecionado constitui erro semântico.
  • Padrões de listas ainda não são suportados; o parser deve emitir PAR001.
_
Keywords

Descricao

O caractere underscore (`_`) atua como curinga (wildcard) universal e padrão de descarte na linguagem TheFlux. É utilizado como braço catch-all em estruturas `route`, como padrão universal em expressões `match` (garantindo exaustividade em enums e tipos literais), e como descarte de campos na desestruturação de structs, registros e variantes de enums.

Sintaxe

"kw">route {
      <condição> ==> { <bloco> }
      _          ==> { <"kw">fallback> }
}
"kw">match (<expressão>) {
      <padrão> ==> <expressão_ou_bloco>
      _        ==> <"kw">fallback>
}
{ .campo1: <padrão>, .campo2: _ }

Pseudocodigo

ESCOLHER(estado):
    CASO 0: pronto()
    PADRAO(_): ignora_qualquer_outro()   // curinga universal

Usos

Braço catch-all em route

Captura qualquer condição não atendida pelos braços anteriores em um bloco route.

"kw">route {
      status == "ativo"    ==> { "kw">print("Conexao ativa") }
      status == "bloqueio" ==> { "kw">print("Acesso bloqueado") }
      _                    ==> { "kw">print("Status desconhecido") }
}

Padrão wildcard universal em match

Corresponde a qualquer valor não coberto anteriormente, garantindo exaustividade.

"kw">match (codigo) {
      200 ==> "kw">print("Sucesso")
      404 ==> "kw">print("Nao encontrado")
      _   ==> "kw">print("Outro codigo: padrao curinga")
}

Descarte de campos em desestruturação

Permite ignorar campos específicos durante o pattern matching de estruturas ou registros.

"kw">match (evento) {
      { .tipo: "sensor", .leitura: val } ==> "kw">print("Leitura: " + val)
      { .tipo: "alerta", .leitura: _ }   ==> "kw">print("Alerta sem telemetria")
      _                                  ==> "kw">print("Evento ignorado")
}

Restricoes

  • Em estruturas route, o braço wildcard `_` deve ser obrigatoriamente o último braço quando presente.
  • Em expressões match, o padrão wildcard `_` sem guarda (guard) captura qualquer valor e encerra a exaustividade.
  • Braços posicionados após um `_` incondicional geram erro semântico de código inalcançável.
  • Pode ser utilizado para ignorar campos individuais em padrões de struct, enum ou registros anônimos.
fail
Keywords

Descricao

Status de falha usado na instrução `emit(fail, ...)`. Indica que a função encontrou um erro ou condição excepcional e devolve um struct de resultado com `.sta == "fail"`. O chamador captura o resultado pelos campos `.sta`, `.val` e `.msg`, ou despacha o fluxo com o operador `?`. O runtime também gera o status `fail` automaticamente quando ocorre divisão por zero (mensagem "divisao por zero").

Sintaxe

"kw">emit("kw">fail, <identificador>, "<mensagem>")

Pseudocodigo

SE erro_detectado:
    EMITIR_FALHA(valor_parcial, "motivo")   // status de falha

Usos

Emit fail em caminho de erro

Devolve status de erro em um braço de route; o chamador lê .sta, .val e .msg.

"kw">function (validar) (idade: "type">int64) "kw">as "type">int64 {
      "kw">route {
            idade < 18 ==> {
                  "kw">emit("kw">fail, idade, "menor de idade")
            }
            _ ==> {
                  "kw">emit("kw">nice, idade, "validacao concluida")
            }
      }
}

"kw">imut "kw">as "type">int64: r = validar(15)
"kw">print(r.sta)     #L "">fail"
"kw">print(r.val)     #L 15
"kw">print(r.msg)     #L "menor de idade"

Fail gerado automaticamente e propagado com ?

Divisão por zero gera o status fail sem emit explícito; o operador ? despacha para o braço fail.

"kw">function (dividir) (dividendo: "type">int64, divisor: "type">int64) "kw">as "type">int64 {
      "kw">mut "kw">as "type">int64: resultado = (dividendo /i divisor) ? {
            ==> "kw">emit("kw">fail, divisor, "divisao por zero")
            ==> "kw">emit("kw">nice, resultado, "divisao executada")
      }
}

Restricoes

  • `fail` só pode ser usado como status do primeiro argumento de `emit()` e como braço `==> emit(fail, ...)` do operador `?` (o braço fail vem antes do braço nice).
  • O valor de `emit(fail, ...)` deve ser um identificador declarado (sem literais nem expressões).
  • A mensagem é obrigatória e deve ser string literal ou interpolada.
  • Divisão por zero gera o status `fail` automaticamente, com mensagem 'divisao por zero'.

Operadores

Descricao

Operadores de manipulação bitwise para inteiros. Incluem AND, OR, XOR, NOT bitwise, deslocamento à esquerda (<<), à direita com sinal (>>) e à direita com preenchimento zero (>>>).

Sintaxe

<expr> & <expr>     # AND bitwise
<expr> | <expr>     # OR bitwise
<expr> ^ <expr>     # XOR bitwise

<expr> >> <expr>    # Deslocamento à direita (com sinal)
<expr> >>> <expr>   # Deslocamento à direita (zero-fill)

Usos

Operações bitwise básicas

AND, OR, XOR e NOT em inteiros.

"kw">mut "kw">as "type">int64: b= 10  # 1010
"kw">print(a & b)   # 8  (1000)
"kw">print(a | b)   # 14 (1110)
"kw">print(a ^ b)   # 6  (0110)

Deslocamento de bits à esquerda e à direita.

"kw">mut "kw">as "type">int64: a= 12

..
Operadores

Descricao

O operador .. (range) tem dois usos: cria intervalos numéricos inclusivos para iteração em infinite (a .. b), e especifica fatias (slices) em coleções e strings [start .. end] ou (start .. end). O range é inclusivo em ambas as extremidades. Veja também KW_slices.yaml para o guia completo de slices.

Sintaxe

<início> .. <fim>                     # Range numérico para iteração
[<início> .. <fim>]                   # Slice em "type">list/"type">data/"type">tensor
[.. <fim>]                            # Slice do início até <fim>
[<início> ..]                         # Slice de <início> até o final
[..]                                  # Slice completo (cópia superficial)
(<início> .. <fim>)                   # Slice em "type">string (após identificador)
(..<fim>)                             # Slice de "type">string do início até <fim>
(<início> ..)                         # Slice de "type">string de <início> até o final
(..)                                  # Slice de "type">string completo

Pseudocodigo

intervalo := 1 .. 10   // range numerico inclusivo

Usos

Range para iteração

Itera sobre um intervalo numérico inclusivo.

"kw">infinite (i "kw">in 1 .. 5) {
    "kw">print(i)  # 1, 2, 3, 4, 5
}
"kw">infinite (i "kw">in -4 .. 4) {
    "kw">print(i)  # -4, -3, -2, -1, 0, 1, 2, 3, 4
}

Slice de lista

Extrai uma fatia de uma lista.

"kw">mut "kw">as "type">list: valores= [10, 20, 30, 40, 50]
"kw">print(valores[..])       # [10, 20, 30, 40, 50]
"kw">print(valores[..3])      # [10, 20, 30]
"kw">print(valores[2..])      # [30, 40, 50]
"kw">print(valores[2..4])     # [30, 40]

Slice de string

Extrai uma substring usando parênteses após o identificador.

"kw">mut "kw">as "type">string: texto= "flux"
"kw">print(texto(..))      # flux
"kw">print(texto(2..3))    # lu

Restricoes

  • O range a..b é inclusivo em ambas as extremidades.
  • Range descendente (a > b) é permitido e itera do maior ao menor.
  • Índices em list/string são 1-based e o fim do slice é inclusivo.
  • Set/map não suportam slice.
  • Slice com passo só é suportado em tensor; em list/string gera erro.
  • A sintaxe de slice de string usa parênteses (texto(2..3)); colchetes em string não são suportados.
  • .. em route with subject é um wildcard (sempre True).
slices
Operadores

Descricao

Slices extraem fatias de coleções e strings usando o operador de range .. dentro de delimitadores. O delimitador depende do tipo: colchetes [ ] para list, data e tensor; parênteses ( ) para string. O range é inclusivo em ambas as extremidades e os índices são 1-based.

Sintaxe

lista[ .. ]              # Slice completo (cópia)
lista[x .. ]             # De x até o final
lista[ .. y]             # Do início até y
lista[x .. y]            # De x até y (inclusivo)
texto( .. )              # String completa (cópia)
texto(x .. )             # Substring de x até o final
texto( .. y)             # Substring do início até y
texto(x .. y)            # Substring de x até y (inclusivo)

Pseudocodigo

numeros := [1, 2, 3, 4, 5]
fatia   := numeros[2..4]   // extrai subcolecao

Usos

Slice de lista

Extrai uma fatia de uma list com colchetes.

"kw">mut "kw">as "type">list "kw">of "type">int64: valores = [10, 20, 30, 40, 50]
"kw">print(valores[ .. ])     # [10, 20, 30, 40, 50]
"kw">print(valores[ .. 3])    # [10, 20, 30]
"kw">print(valores[2 .. ])    # [20, 30, 40, 50]
"kw">print(valores[2 .. 4])   # [20, 30, 40]

Slice de tensor

Fatia a primeira dimensão de um tensor com colchetes; passo é suportado apenas em tensor.

"kw">mut "kw">as "type">tensor[4] "kw">of "type">int64: t = "type">tensor([1, 2, 3, 4])
"kw">print(t[2 .. 4])         # [2, 3, 4]
"kw">print(t[1 .. 4 .. 2])    # [1, 3]

Slice de data

Fatia uma lista de data (registros) com colchetes.

"kw">mut "kw">as "type">list "kw">of "type">data: itens = [{a: 1}, {a: 2}, {a: 3}]
"kw">print(itens[2 .. 3])     # [{a: 2}, {a: 3}]

Slice de string

Extrai uma substring com parênteses; índices contam codepoints Unicode.

"kw">mut "kw">as "type">string: texto = "flux"
"kw">print(texto( .. ))       # flux
"kw">print(texto( .. 3))      # flu
"kw">print(texto(2 .. ))      # lux
"kw">print(texto(2 .. 3))     # lu

Restricoes

  • Índices são 1-based e o fim é inclusivo.
  • Início, fim ou ambos podem ser omitidos; omitidos assumem o início/fim da coleção.
  • Fora do intervalo válido (1..tamanho) ou início maior que fim gera erro em tempo de execução.
  • Passo (sintaxe `[início .. fim .. passo]`) só é suportado em tensor; em list e string gera erro.
  • Set e map não suportam slice.
  • O delimitador segue o tipo: [ ] para list/data/tensor, ( ) para string.

route
Keywords

Descricao

Avalia condições em ordem e executa o bloco correspondente ao primeiro braço cuja condição seja verdadeira. O braço wildcard (`_`) captura qualquer valor não coberto pelos braços anteriores. Pode substituir cadeias de if/else if/else.

Sintaxe

"kw">route {
      <condição> ==> <ação>
      <condição> ==> <ação>
      _          ==> <"kw">fallback>
}

Pseudocodigo

ROTA:
    CASO cond1: bloco1
    CASO cond2: bloco2
    PADRAO: bloco_fallback
// equivalente a cadeias de se/ entao / senao

Usos

Rota com condição verdadeira

Executa o braço cuja condição é verdadeira.

"kw">route {
      "kw">true  ==> { "kw">print("Verdadeiro") }
      "kw">false ==> { "kw">print("Falso") }
}

Rota com wildcard

O braço wildcard (`_`) executa quando nenhuma condição anterior é verdadeira.

"kw">route {
      "kw">false ==> { "kw">print("Nao Executa") }
      _     ==> { "kw">print("Fallback") }
}

Rota com múltiplos braços

Apenas o primeiro braço verdadeiro é executado.

"kw">route {
      1 == 1 ==> { "kw">print("um") }
      2 == 2 ==> { "kw">print("dois") }
      _      ==> { "kw">print("nenhum") }
}

Restricoes

  • Braços são avaliados de cima para baixo; o primeiro verdadeiro é executado.
  • O wildcard (`_`) deve ser o último braço, se usado.
  • Se nenhum braço for verdadeiro e não houver wildcard, nada é executado.

Descricao

Interrompe imediatamente o loop `infinite` mais interno, transferindo o controle para a instrução seguinte ao bloco do loop.

Sintaxe

"kw">break

Pseudocodigo

REPETIR PARA SEMPRE:
    corpo...
    SE pronto: INTERROMPER   // "kw">break sai do loop mais interno

Usos

Break simples

Sai do loop infinito imediatamente.

"kw">infinite {
      "kw">print("rodei")
      "kw">break
}

Break após condição

Break condicional dentro do loop.

"kw">mut "kw">as "type">int64: i = 0
"kw">infinite {
      i = i + 1
      "kw">route {
            i == 3 ==> { "kw">break }
            _ ==> { "kw">print(i) }
      }
}

Restricoes

  • Só pode ser usado dentro de um bloco `infinite`.
  • Break encerra apenas o loop mais interno.

Sintaxe

"kw">continue

PARA CADA item DENTRO DE colecao:
    SE invalido(item): CONTINUAR    // pula para a proxima iteracao

Continue simples

Pula a iteração atual e continua na próxima.

"kw">mut "kw">as "type">int64: i = 0
"kw">infinite {
      i = i + 1

agent
Keywords

Descricao

Declara um agente em arquivos .fdsl. Agentes são unidades modulares que encapsulam operações (op). O nome do agente deve estar em PascalCase. Agentes são proibidos em arquivos .flux.

Sintaxe

"kw">agent (<nome_PascalCase>) {
      <declarações>
      "kw">op <nome_camelCase> (["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador> [, ["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador> ...]) ["kw">as <tipo_retorno>] ==> {
            <instruções>
            "kw">emit("kw">nice | "kw">fail, <identificador>, "<mensagem>")
      }
      ...
}

Pseudocodigo

AGENTE Veiculo:
    OPERACAO acelerar(velocidade):
        ...
// unidade modular que encapsula operacoes ("kw">op)

Usos

Agente simples

Agente que declara operações sem parâmetros.

"kw">agent (AgentOfMath) {
      "kw">op dot ==> {
            "kw">print("Produto Escalar")
      }
      "kw">op crux ==> {
            "kw">print("Produto Vetorial")
      }
}

Agente com operações parametrizadas

Agente com ops que recebem parâmetros nomeados ([mut | imut | as] <tipo>: <id>), retorno opcional ([as <tipo>]) e bloco com ==>.

"kw">agent (AgentOfMath) {
      "kw">op dot ("kw">as "type">int64: x, "kw">as "type">int64: y) "kw">as "type">int64 ==> {
            "kw">mut "kw">as "type">int64: res = x + y
            "kw">emit("kw">nice, res, "ok")
      }
      "kw">op normalizarNome ("kw">as "type">string: nome) "kw">as "type">string ==> {
            "kw">emit("kw">nice, nome, "ok")
      }
}

Agente com estado

Agente que encapsula estado com declarações mut/imut.

"kw">agent (AgenteContador) {
      "kw">mut "kw">as "type">int64: total = 0
      "kw">op incrementar ("kw">as "type">int64: passo) "kw">as "type">int64 ==> {
            total =+ passo
            "kw">emit("kw">nice, total, "ok")
      }
}

Restricoes

  • O nome do agente deve estar em PascalCase.
  • Um agente pode implementar no máximo um contrato usando a cláusula `impl`.
  • Operações (`op`) declaradas no corpo do agente seguem a sintaxe `op nomeCamelCase ([mut | imut | as] <tipo>: <id> ...) [as <tipo>] ==> { <corpo> }`.
  • Arquivos `.fdsl` não possuem `program`; apenas agentes e contratos são permitidos.
  • O corpo de um agente é delimitado por chaves `{}` e pode conter variáveis, funções e operações.
  • Agentes podem ser importados em arquivos `.flux` através da declaração `use`.
contract
Keywords

Descricao

Declara um contrato que define um conjunto de assinaturas de operações (op) que um agente (agent) pode implementar. O contrato é uma interface que especifica nomes, parâmetros e tipos de retorno sem implementação.
Contratos são válidos apenas em arquivos .fdsl. O nome do contrato deve estar em PascalCase.

Sintaxe

"kw">contract (<Nome_PascalCase>) {
      "kw">op <nome_camelCase> (["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador> [, ...]) ["kw">as <tipo_retorno>]
      "kw">op <nome_camelCase> () ["kw">as <tipo_retorno>]
      ...
}

Pseudocodigo

CONTRATO Operavel:
    assinatura ligar()
    assinatura desligar()
// conjunto de assinaturas que um agente pode implementar

Usos

Contrato com operações simples

Contrato com ops sem parâmetros.

"kw">contract (Readable) {
      "kw">op read () "kw">as "type">int64
}

Contrato com operações parametrizadas

Contrato para operações matemáticas básicas com parâmetros nomeados.

"kw">contract (OperacoesBasicas) {
      "kw">op somar ("kw">as "type">int64: a, "kw">as "type">int64: b) "kw">as "type">int64
      "kw">op subtrair ("kw">as "type">int64: a, "kw">as "type">int64: b) "kw">as "type">int64
      "kw">op multiplicar ("kw">as "type">int64: a, "kw">as "type">int64: b) "kw">as "type">int64
      "kw">op dividirInteiro ("kw">as "type">int64: a, "kw">as "type">int64: b) "kw">as "type">int64
}

Múltiplos contratos no mesmo arquivo

Dois contratos declarados sequencialmente em um .fdsl.

"kw">contract (ReadOp) {
      "kw">op read () "kw">as "type">int64
}
"kw">contract (WriteOp) {
      "kw">op write () "kw">as "type">int64
}

Restricoes

  • O nome do contrato deve estar em PascalCase.
  • Operações em contratos não podem ter corpo (apenas assinatura).
  • Deve haver pelo menos uma operação no contrato.
  • Contratos são válidos apenas em arquivos .fdsl (não em .flux).
  • Agentes implementam contratos via a cláusula `impl` na declaração `agent`.
function
Keywords

Descricao

Declara uma função nomeada e reutilizável com parâmetros tipados e retorno opcional (via `as <tipo_retorno>`). Parâmetros são imutáveis (`imut`) por padrão quando o modificador de mutabilidade for omitido (ex: `as <tipo>: <identificador>`); para permitir reatribuição ao parâmetro no escopo local, declare-o explicitamente como `mut as <tipo>: <identificador>`. Parâmetros do mesmo tipo e mutabilidade podem ser agrupados em uma única declaração (`[mut | imut | as] <tipo>: <id1>, <id2>, ..., <idN>`); grupos com tipagens distintas são separados por `;`. O corpo da função deve terminar com um `emit` terminal que devolve um struct implícito de resultado de três campos (`.sta`, `.val`, `.msg`). Se o campo de retorno não for explicitado no chamador, o campo padrão de avaliação é o `.val`. Funções são declaradas no topo do arquivo (.flux) ou no corpo de agentes/impl (.fdsl), antes do `program`, e podem ser chamadas por `nome(args)`; o resultado inteiro fica disponível via variável (`r = calc(5)`) e cada campo é lido com acesso nomeado.

Sintaxe

"kw">function (<nome_camelCase>) (["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador1>, ..., <identificadorN> [; ["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador1>, ..., <identificadorN>]) ["kw">as <tipo_retorno>] {
      <instruções>
      "kw">emit("kw">nice | "kw">fail, <identificador>, "<mensagem>")
}

Pseudocodigo

FUNCAO somar(a, b):
    RETORNAR a + b
FIM FUNCAO

Usos

Função com retorno e consumo dos campos

Função que calcula um valor; o chamador lê o struct de resultado via campos .sta, .val e .msg. Os parâmetros são imutáveis por padrão (as <tipo>: x).

"kw">function (calc) ("kw">as "type">int64: x) "kw">as "type">int64 {
      "kw">mut "kw">as "type">int64: resultado = x * 2
      "kw">emit("kw">nice, resultado, " dobro ok")
}

"kw">program (Main) {
      "kw">imut "kw">as "type">int64: r = calc(5)
      "kw">print(r.sta)     # "">nice"
      "kw">print(r.val)     # 10
      "kw">print(r.msg)     # "dobro ok"
}

Função com parâmetros agrupados

Parâmetros do mesmo tipo e mutabilidade compartilham uma única declaração (`as int64: dividendo, divisor`); grupos com tipagens distintas são separados por `;`.

"kw">function (epar) ("kw">mut "kw">as "type">int64: dividendo, divisor ; "kw">imut "kw">as "type">float64: PI) "kw">as "type">float64 {
      "kw">mut "kw">as "type">float64: quociente = dividendo /f divisor * PI
      "kw">emit("kw">nice, quociente, "calculo ok")
}

"kw">program (Main) {
        "kw">print(epar(4, 2, 3.14)) # imprime 6.28
}

Função com parâmetro mutável local

Parâmetros declarados com `mut as <tipo>:` podem ser reatribuídos dentro do corpo da função.

"kw">function (acumular) ("kw">mut "kw">as "type">int64: total, "kw">as "type">int64: incremento) "kw">as "type">int64 {
      total =+ incremento
      "kw">emit("kw">nice, total, "acumulado com sucesso")
}

"kw">program (Main) {
      "kw">print(acumular(10, 5)) # imprime 15
}

Função com avaliação direta de valor

Quando chamada em expressões ou print diretamente, avalia o campo .val por padrão.

"kw">function (dobro) ("kw">as "type">int64: n) "kw">as "type">int64 {
      "kw">mut "kw">as "type">int64: res = n * 2
      "kw">emit("kw">nice, res, "ok")
}

"kw">program (Main) {
      "kw">print(dobro(21)) # imprime 42
}

Função que falha com emit(fail)

A função pode terminar em `emit(fail, ...)`; os três campos seguem preenchidos com o status de erro.

"kw">function (validar) ("kw">as "type">int64: idade) "kw">as "type">int64 {
      "kw">route {
            idade < 18 ==> {
                  "kw">emit("kw">fail, idade, "menor de idade")
            }
            _ ==> {
                  "kw">emit("kw">nice, idade, "validacao concluida")
            }
      }
}

"kw">program (Main) {
      "kw">imut "kw">as "type">int64: r = validar(15)
      "kw">print(r.sta)     # "">fail"
      "kw">print(r.val)     # 15
      "kw">print(r.msg)     # "menor de idade"
}

Restricoes

  • O nome da função deve estar em camelCase: `function nomeCamelCase(...)`.
  • Parâmetros seguem a convenção `[mut | imut | as] <tipo>: <identificador>` e identificadores em snake_case.
  • Parâmetros de mesmo tipo e mutabilidade podem ser agrupados em uma única declaração (ex: `mut as int64: dividendo, divisor`); grupos com tipagens distintas são separados por `;`.
  • Parâmetros são imutáveis (`imut`) por padrão quando declarados apenas com `as <tipo>: nome`.
  • Funções com tipo de retorno `as <tipo>` devem terminar obrigatoriamente com o comando `emit`.
  • Funções são declaradas no topo do arquivo (.flux) ou no corpo de agentes/impl (.fdsl), antes do `program`.
  • Funções sem tipo de retorno são void; funções com retorno exigem `emit` em todos os caminhos de execução.
  • `emit` aceita apenas um identificador declarado como valor; expressões e literais não são permitidos.
  • `emit` encerra a execução e devolve o struct de resultado com `.sta`, `.val` e `.msg`.
  • A declaração de funções é proibida dentro do bloco `program`.
  • Funções recursivas são suportadas e chamadas com sintaxe padrão `nome(args)`.
use
Keywords

Descricao

Importa agentes ou operações de agentes de outros módulos. Pode importar um agente inteiro com alias, uma operação específica com alias, ou um grupo de operações de um agente.

Sintaxe

"kw">use <AgentePascalCase> "kw">as <AliasPascalCase>
"kw">use <AgentePascalCase>::<operacao_camelCase> "kw">as <alias_camelCase>
"kw">use <AgentePascalCase>::{ <"kw">op> ["kw">as <alias>], ... }

Pseudocodigo

USAR Modulo::Operacao        // importa operacao especifica
USAR Calc COMO Aritmetica    // importa agente com alias

Usos

Importar agente com alias

Importa um agente completo com um alias; operações são usadas via Alias::op.

"kw">use AgentOfPrint "kw">as AP
"kw">use AgentOfMath "kw">as AM

Importar operação específica

Importa uma operação específica de um agente com alias; a operação passa a ser chamável pelo alias.

"kw">use AgentOfMath::dot "kw">as produtoEscalar

Importar grupo de operações

Importa múltiplas operações de um agente.

"kw">use AgentOfMath::{
    dot "kw">as produtoEscalar,
    crux,
    inverse
}

Uso de agente importado

Utiliza operações do agente importado via alias e ::.

AP::printNome
AM::printNome

Uso de operação importada com alias

Chama diretamente a operação importada pelo alias.

produtoEscalar(2, 3)
meuPrint()

Restricoes

  • Nomes de agentes e aliases de agentes devem estar em PascalCase.
  • Nomes de operações e aliases de operações devem estar em camelCase.
  • Aliases de operações são chamados como função: `alias(args)`.
  • Aliases de agentes são usados com `::` para acessar operações: `Alias::op(args)`.
  • Declarações `use` devem vir no início do arquivo, antes de outras declarações.
op
Keywords

Descricao

Declara uma operação dentro de um agente (agent) em arquivos .fdsl ou uma assinatura de operação dentro de um contrato (contract). Operações são funções encapsuladas no agente com retorno opcional (via `as <tipo_retorno>`). Parâmetros são imutáveis (`imut`) por padrão quando o modificador de mutabilidade for omitido (ex: `as <tipo>: <identificador>`); para permitir reatribuição ao parâmetro no escopo local, declare-o explicitamente como `mut as <tipo>: <identificador>`. O corpo da operação deve terminar com um `emit` terminal que devolve um struct implícito de resultado (.sta, .val, .msg). O nome da operação deve estar em camelCase.

Sintaxe

# Op com corpo — dentro de "kw">agent; parâmetros no formato (["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador>, ...);
# retorno opcional com ["kw">as <tipo_retorno>] e bloco de corpo com ==>.
"kw">op <nome_camelCase> (["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador> [, ["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador> ...]) ["kw">as <tipo_retorno>] ==> {
      <instruções>
      "kw">emit("kw">nice | "kw">fail, <identificador>, "<mensagem>")
}
"kw">op <nome_camelCase> ==> {
      <instruções>
}  # sem parâmetros nem retorno explícito

# Assinatura sem corpo — dentro de "kw">contract; parâmetros com tipo e identificador.
"kw">op <nome_camelCase> (["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador> [, ["kw">mut | "kw">imut | "kw">as] <tipo>: <identificador> ...]) ["kw">as <tipo_retorno>]

Pseudocodigo

AGENTE Conversor:
    OPERACAO dobrar(x):
        RETORNAR x * 2

Usos

Operação com parâmetros e retorno

Operação completa em um agente. Parâmetros nomeados ([mut | imut | as] <tipo>: <id>); retorno com [as <tipo>] e bloco com ==>.

"kw">op dobro ("kw">as "type">int64: x) "kw">as "type">int64 ==> {
      "kw">mut "kw">as "type">int64: resultado = x * 2
      "kw">emit("kw">nice, resultado, "ok")
}

Operação com parâmetro mutável local

Parâmetros declarados com `mut as <tipo>:` podem ser reatribuídos dentro do corpo da operação.

"kw">op acumular ("kw">mut "kw">as "type">int64: total, "kw">as "type">int64: incremento) "kw">as "type">int64 ==> {
      total =+ incremento
      "kw">emit("kw">nice, total, "acumulado com sucesso")
}

Operação sem parâmetros nem retorno

Operação simplificada sem parâmetros.

"kw">op printNome ==> {
      "kw">print("Andre Luiz Fassone Canova")
}

Assinatura em contrato

Operação como assinatura dentro de um contrato (sem corpo). Parâmetros com tipo e identificador.

"kw">contract CalculadoraContrato {
      "kw">op dobro ("kw">as "type">int64: valor) "kw">as "type">int64
      "kw">op soma ("kw">as "type">int64: lhs, "kw">as "type">int64: rhs) "kw">as "type">int64
}

Restricoes

  • O nome da operação deve estar em camelCase: `op nomeDaOperacao`.
  • Parâmetros seguem a convenção `[mut | imut | as] <tipo>: <identificador>` e identificadores devem estar em snake_case.
  • Parâmetros são imutáveis (`imut`) por padrão quando declarados com `as <tipo>: <id>`; para permitir reatribuição local, declare como `mut as <tipo>: <id>`.
  • Op com corpo é válida dentro do corpo de um agente (`agent`) e utiliza `==> { <corpo> }`.
  • Op sem corpo é válida dentro de um contrato (`contract`).
  • O corpo deve terminar obrigatoriamente com um comando `emit` terminal quando possuir retorno.
  • `emit` é válido apenas dentro do corpo de uma função (`function`) ou operação (`op`).
enum
Keywords

Descricao

Declara um tipo enum (união discriminada) inspirado em Rust. Um enum representa um conjunto fechado de variantes, onde cada variante pode ser unitária (sem payload) ou conter campos nomeados (payload). Variantes com payload utilizam a mesma sintaxe de campos nomeados das structs (ponto obrigatório, campos em linhas separadas), permitindo construção e desestruturação simétricas através do pattern matching. O discriminante (identificador numérico interno da variante) é sempre gerado automaticamente pelo compilador, na ordem de declaração, e não pode ser controlado pelo programador.

Sintaxe

enum (<NomePascalCase>) {

    <VariantePascalCase>

    <VariantePascalCase>(

        .<campo_snake_case>: <tipo>

        ...

    )

    ...

}

Pseudocodigo

TIPO CORES:
    VERMELHO
    VERDE
    AZUL (intensidade)
// uniao discriminada: conjunto fechado de variantes

Usos

Enum com variantes unitárias

Declara variantes sem payload.

enum (Estado) {

    Aberto
    Fechado
    Suspenso

}

Enum com payload

Declara variantes contendo campos nomeados, um por linha.

enum (Resultado) {

    Ok(

        .valor: "type">int64

    )

    Erro(

        .mensagem: "type">string

    )

}

Inicialização de variantes

Constrói variantes utilizando campos nomeados prefixados por ponto. Todos os campos declarados devem ser fornecidos.

enum (Estado) {
      Aberto
}
"kw">program (T) {
      "kw">mut "kw">as Estado: estado = Estado::Aberto
      "kw">print(estado)
}
enum (Resultado) {
      Ok(
            .valor: "type">int64
      )
      Erro(
            .mensagem: "type">string
      )
}
"kw">program (T) {
      "kw">mut "kw">as Resultado: resposta = Resultado::Ok(
            .valor: 42
      )
      "kw">print(resposta)
}
enum (Mensagem) {
      Texto(
            .conteudo: "type">string
      )
}
"kw">program (T) {
      "kw">mut "kw">as Mensagem: msg = Mensagem::Texto(
            .conteudo: "Ola Mundo"
      )
      "kw">print(msg)
}

Pattern matching

Variantes são desestruturadas utilizando exatamente a mesma sintaxe empregada durante sua construção. O padrão pode selecionar um subconjunto dos campos (os demais são ignorados), com bind de nome, literal ou wildcard (_).

enum (Resultado) {
      Ok(
            .valor: "type">int64
      )
      Erro(
            .mensagem: "type">string
      )
}
"kw">program (T) {
      "kw">mut "kw">as Resultado: resposta = Resultado::Ok(.valor: 1)
      "kw">match resposta {
            Resultado::Ok(.valor: valor) ==> "kw">print(valor)
            Resultado::Erro(.mensagem: mensagem) ==> "kw">print(mensagem)
            _ ==> "kw">print("desconhecido")
      }
}

Restricoes

  • O nome do enum deve estar em PascalCase.
  • O keyword enum é escrito em minúsculo.
  • Os nomes das variantes devem estar em PascalCase.
  • Os nomes dos campos devem utilizar snake_case.
  • Todo campo é obrigatoriamente prefixado por ponto (.), tanto na declaração quanto na construção e desestruturação.
  • Cada campo ocupa uma linha própria; campos são separados por quebra de linha (EOL), nunca por vírgula.
  • O enum deve possuir pelo menos uma variante.
  • Os nomes das variantes devem ser únicos.
  • Os nomes dos campos devem ser únicos dentro de cada variante.
  • Variantes unitárias não utilizam parênteses.
  • Variantes são acessadas utilizando o operador ::.
  • Variantes com payload são inicializadas utilizando campos nomeados prefixados por ponto.
  • A ordem dos campos durante a inicialização é irrelevante.
  • Todos os campos declarados devem ser fornecidos na construção.
  • Padrões de match podem selecionar um subconjunto dos campos; campos não mencionados são ignorados.
  • A construção e a desestruturação utilizam exatamente a mesma estrutura sintática.
struct
Keywords

Descricao

Declara um tipo struct (registro) composto por um conjunto fixo de campos nomeados. Cada campo pode ser mutável (mut) ou imutável (imut). Uma struct representa um único formato de dados e possui exatamente um construtor nominal. A mesma sintaxe utilizada para construir uma struct é reutilizada pelo pattern matching para desestruturá-la, tornando construção e desconstrução operações simétricas. O nome da struct deve estar em PascalCase.

Sintaxe

struct (<NomePascalCase>) {

    "kw">mut: .<campo_snake_case>: <tipo>

    "kw">imut: .<CAMPO_SCREAMING_SNAKE_CASE>: <tipo>

    ...

}

Pseudocodigo

REGISTRO Pessoa:
    campo nome: "type">string
    campo idade: "type">int64
// valores nomeados, conjunto fixo de campos

Usos

Struct com campos mutáveis e imutáveis

Declara uma struct contendo campos mutáveis e imutáveis.

struct (Evento) {

    "kw">mut: .nome: "type">string

    "kw">imut: .DATA: "type">datetime

    "kw">mut: .contador: "type">int64

}

Inicialização de struct

Inicializa uma struct utilizando campos nomeados. A correspondência dos argumentos ocorre pelo nome dos campos e não pela posição. Cada campo é escrito em uma linha própria, separado por quebra de linha (EOL); o ponto é obrigatório.

Inicializacao

Acesso aos campos

Acessa campos utilizando a notação de ponto.

"kw">print(evento.nome)
evento.contador = evento.contador + 1

Pattern matching

Desestrutura uma struct utilizando exatamente a mesma sintaxe empregada durante sua construção: cada campo em uma linha própria, prefixado por ponto.

"kw">match (evento) {

    Evento(

        .nome: nome

        .quando: quando

        .contador: contador

    ) ==> contador

}

Restricoes

  • O nome da struct deve estar em PascalCase.
  • O keyword struct é escrito em minúsculo.
  • Todo campo é obrigatoriamente prefixado por ponto (.), tanto na declaração quanto na construção e desestruturação.
  • Cada campo ocupa uma linha própria; campos são separados por quebra de linha (EOL), nunca por vírgula.
  • Campos mutáveis devem utilizar snake_case.
  • Campos imutáveis devem utilizar SCREAMING_SNAKE_CASE.
  • Os nomes dos campos devem ser únicos dentro da struct.
  • Uma struct deve possuir pelo menos um campo.
  • Structs possuem exatamente um construtor.
  • Campos são inicializados utilizando argumentos nomeados prefixados por ponto.
  • A ordem dos campos durante a inicialização é irrelevante; a correspondência ocorre pelo nome.
  • Todos os campos obrigatórios devem ser inicializados.
  • Campos declarados como imutáveis não podem receber atribuição após a construção da instância.
  • A construção e a desestruturação utilizam exatamente a mesma estrutura sintática.
mut
Keywords

Descricao

Declara uma variável mutável, com valor inicial explícito opcional. Sem valor inicial, a variável recebe o valor padrão do tipo (0, 0.0, false, string vazia etc.). Múltiplas variáveis podem ser declaradas com vírgulas na forma principal (`mut as <tipo>: a, b = 42`).

Sintaxe

"kw">mut "kw">as <tipo>: <identificador> [, <identificador> ...] [= <expressão>]

Pseudocodigo

VARIAVEL contador := 0
contador := contador + 1    // reatribuivel

Usos

Declaração com tipo e valor inicial

Declara uma variável mutável com tipo explícito e valor inicial.

"kw">mut "kw">as "type">int64: contador = 0
"kw">mut "kw">as "type">string: nome = "TheFlux"

Declaração com valor padrão do tipo

Sem valor inicial, a variável recebe o valor padrão do tipo.

"kw">mut "kw">as "type">int64: contador
"kw">mut "kw">as "type">string: nome

Declaração múltipla em linha

Várias variáveis na forma principal, separadas por vírgula; tipo e valor inicial são compartilhados entre todas.

"kw">mut "kw">as "type">int64: a, b = 42

Restricoes

  • Os identificadores devem seguir snake_case; a implementação emite uma sugestão (SUG) quando o nome não segue a convenção (não é erro).
  • Variáveis mutáveis podem ser reatribuídas com `=` e com operadores compostos: =+, =-, =*, =/i, =/r, =/f, =^e, =^r, =^, =&, =|, =~, =<<, =>>, =>>>.
  • O tipo é obrigatório após `as` (não há forma sem tipo).
  • Múltiplas variáveis em uma única declaração são aceitas apenas na forma principal, com vírgulas entre os identificadores (`mut as <tipo>: a, b = 42`); o tipo e o valor inicial são compartilhados. Valores diferentes exigem declarações separadas.
imut
Keywords

Descricao

Declara uma constante imutável com valor inicial obrigatório. Uma vez atribuída, não pode ser reatribuída; a reatribuição gera erro semântico (SEM001). Múltiplas constantes podem ser declaradas na forma principal com vírgulas, desde que compartilhem o mesmo valor inicial.

Sintaxe

"kw">imut "kw">as <tipo>: <identificador> [, <identificador> ...] = <expressão>

Pseudocodigo

CONSTANTE maximo := 100     // valor fixo, nao reatributivel

Usos

Declaração de constante

Declara uma constante imutável com tipo explícito e valor inicial obrigatório.

"kw">imut "kw">as "type">int64: MAX_TENTATIVAS = 10
"kw">imut "kw">as "type">string: NOME_APP = "TheFlux"

Declaração múltipla em linha

Várias constantes na forma principal, separadas por vírgula; todas recebem o mesmo valor inicial.

"kw">imut "kw">as "type">float64: PI1, PI2 = 3.14159

Restricoes

  • Os identificadores devem seguir SCREAMING_SNAKE_CASE; a implementação emite uma sugestão (SUG) quando o nome não segue a convenção (não é erro).
  • O valor inicial é obrigatório; a omissão gera erro SEM001 (imut não tem valor padrão).
  • Não pode ser reatribuída após a declaração; reatribuição com `=` ou operadores compostos gera erro SEM001.
  • O tipo é obrigatório após `as` (não há forma sem tipo).
  • Múltiplas constantes em uma única declaração são aceitas apenas na forma principal, com vírgulas entre os identificadores (`imut as <tipo>: A, B = 42`); todas recebem o mesmo valor inicial. Valores diferentes exigem declarações separadas.
ensure
Keywords

Descricao

Operador de cleanup que garante que um bloco de código sempre execute, independentemente de sucesso ou falha da expressão alvo. Preserva o valor original ou re-lança a falha após a execução do bloco.

Sintaxe

'<expressão> "kw">ensure { <bloco_cleanup> }
'

Pseudocodigo

operacao_principal(x)
GARANTIR:               // sempre executa
    liberar_recursos()

Usos

Ensure com sucesso

Bloco de cleanup executado após sucesso, mantendo o valor.

"falhaControlada() ">ensure {\n    ">print(\"cleanup executado\")\n} ">catch 9\n"

Ensure com fallback

Ensure executado antes do fallback em caso de falha.

"kw">mut "kw">as "type">int64: n_par = 4
"kw">mut "kw">as "type">int64: res_par = avaliaNumero(n_par) "kw">fallback {
      (n_par + 1)
} "kw">ensure {
      "kw">print("Ensure sempre executado")
}

Restricoes

  • O bloco ensure sempre executa, independente de sucesso ou falha.
  • Ensure preserva o valor original em caso de sucesso.
  • Ensure re-lança a falha se o bloco não a tratar.
  • Tipo do resultado = tipo da expressão alvo (bloco não tipa a expressão).

impl
Keywords

Descricao

Cláusula usada na declaração de um agente (agent) para indicar que ele implementa um ou mais contratos (contract). O agente deve fornecer uma operação (op) para cada assinatura definida nos contratos, com aridade, parâmetros e tipo de retorno correspondentes.
Suporta múltiplos contratos separados por vírgula. Válido apenas em arquivos .fdsl.

Sintaxe

"kw">agent (<Nome_PascalCase>) "kw">impl <Contrato1>, <Contrato2>, ... {
      "kw">op <nome> ([params]) ["kw">as <tipo>] ==> {
            <corpo>
      }
      ...
}

Pseudocodigo

AGENTE Motor IMPLEMENTA Operavel:
    OPERACAO ligar: ...     // corpo concreto da assinatura
    OPERACAO desligar: ...
// clausula "kw">impl declara os contratos implementados pelo agente

Usos

Implementação de um contrato

Agente que implementa um único contrato.

"kw">agent (AgentOfCalculadora) "kw">impl OperacoesBasicas {
      "kw">op somar ("kw">as "type">int64: a, "kw">as "type">int64: b) "kw">as "type">int64 ==> {
            "kw">mut "kw">as "type">int64: resultado = a + b
            "kw">emit("kw">nice, resultado, "Soma concluida")
      }
      "kw">op subtrair ("kw">as "type">int64: a, "kw">as "type">int64: b) "kw">as "type">int64 ==> {
            "kw">mut "kw">as "type">int64: resultado = a - b
            "kw">emit("kw">nice, resultado, "Subtracao concluida")
      }
}

Implementação de múltiplos contratos

Agente que implementa dois contratos simultaneamente com ops separadas.

"kw">agent (DualAgent) "kw">impl ReadOp, WriteOp {
      "kw">op read () "kw">as "type">int64 ==> {
            "kw">emit("kw">nice, 42, "read")
      }
      "kw">op write () "kw">as "type">int64 ==> {
            "kw">emit("kw">nice, 99, "write")
      }
}

Contrato verificado semânticamente

O verificador semântico checa que todas as ops do contrato estão implementadas com aridade e tipos corretos.

Restricoes

  • O nome do agente deve estar em PascalCase.
  • Nomes de contratos repetidos no mesmo impl são erro semântico.
  • Cada operação de cada contrato deve ser implementada com aridade e tipos correspondentes.
  • Agentes podem ter ops adicionais além das exigidas pelo contrato (ops extras são permitidas).
  • A cláusula `impl` não pode ser usada em arquivos .flux (apenas .fdsl).
input
Keywords

Descricao

Lê uma linha da entrada padrão (stdin) e atribui à variável declarada. Exibe um prompt opcional antes da leitura. A declaração de tipo é obrigatória em TheFlux; o tipo declarado na variável define o tipo esperado do valor digitado.

"kw">input()

"kw">mut "kw">as <tipo>: <variável> = "kw">input(<expressão_prompt>)

LER("Idade: ")
// SE digitado inválido para "type">int64: RE-PERGUNTA "Digite um inteiro, como: 35"

Input tipado como int64

Lê um inteiro. Após Enter, valida que o valor é int64; se não for, volta ao prompt com "Digite um inteiro, como: 35".

"kw">mut "kw">as "type">int64: idade = "kw">input("Introduza a sua idade: ")
"kw">mut "kw">as "type">int64: quantidade = "kw">input()

Lê um texto. Qualquer valor digitado é aceito como string.

  • A declaração de tipo é obrigatória; `input` assume o tipo declarado na variável (`as <tipo>`).
  • A verificação de tipagem ocorre somente depois de pressionar Enter.
  • Se o tipo digitado for incompatível com o tipo declarado, o prompt volta e escreve em cinza `Digite um <tipo>, como: <exemplo>`.
  • O valor lido é compatível com o tipo da variável; pode ser convertido para outros tipos usando as (cast).
emit
Keywords

Descricao

Encerra a função atual devolvendo um struct implícito de resultado com três campos sempre definidos: `.sta` ("nice" | "fail"), `.val` (valor do identificador emitido, tipado pelo `as <tipo>` da função) e `.msg` (mensagem string ou interpolada). `emit` é o statement terminal obrigatório do corpo de uma função. O struct inteiro fica disponível via variável (`r = calc(5)`); depois leia cada campo com acesso nomeado.

Sintaxe

"kw">emit("kw">nice, <identificador>, "<mensagem>")
"kw">emit("kw">fail, <identificador>, "<mensagem>")

Pseudocodigo

FUNCAO calc(x):
    SE invalido(x):
        EMITIR(falha, x, "entrada invalida")
    EMITIR(ok, x * 2, "calculado")   // terminal: encerra a funcao

Usos

Emit nice com retorno e consumo dos campos

Devolve o resultado de sucesso; o chamador lê .sta, .val e .msg.

"kw">function (calc) (x: "type">int64) "kw">as "type">int64 {
      "kw">emit("kw">nice, x, "ok")
}

"kw">program (Main) {
      "kw">imut "kw">as "type">int64: r = calc(5)
      "kw">print(r.sta)     # "">nice"
      "kw">print(r.val)     # 5
      "kw">print(r.msg)     # "ok"
}

Emit fail em caminho de erro

Devolve status de erro em um braço de route; os três campos continuam preenchidos.

"kw">function (dividir) (dividendo: "type">int64, divisor: "type">int64) "kw">as "type">int64 {
      "kw">route {
            divisor == 0 ==> {
                  "kw">emit("kw">fail, divisor, "divisao por zero")
            }
            _ ==> {
                  "kw">mut "kw">as "type">int64: resultado = dividendo /i divisor
                  "kw">emit("kw">nice, resultado, "divisao executada")
            }
      }
}

Emit fail com retorno

Devolve o status de erro junto com o valor e a mensagem.

"kw">function (validar) (idade: "type">int64) "kw">as "type">int64 {
      "kw">route {
            idade < 18 ==> {
                  "kw">emit("kw">fail, idade, "menor de idade")
            }
            _ ==> {
                  "kw">emit("kw">nice, idade, "validacao concluida")
            }
      }
}

"kw">imut "kw">as "type">int64: r = validar(15)
"kw">print(r.sta)     # "">fail"
"kw">print(r.val)     # 15
"kw">print(r.msg)     # "menor de idade"

Restricoes

  • Apenas os status `nice` (sucesso) e `fail` (erro) são permitidos.
  • `emit` é o statement terminal do corpo de uma função — nada pode vir depois.
  • `value` é um único identificador declarado (sem lista, sem expressão).
  • A mensagem deve ser string literal ou string interpolada.
  • Funções com `as <tipo>` de retorno devem ter `emit` em todo caminho de execução (loops não contam).

"kw">infinite (fruta "kw">in ["uva", "banana", "cereja"]) {

Sem tipo explícito, o literal é int64.

  • Não há sufixo de tipo no literal (ex: 42i32) — o tipo é determinado pela declaração.
  • Zero à esquerda não é permitido em literais inteiros (ex: 007 é inválido).

  • Ver também KW_TYPE_int.yaml (tipo) — tipos e literais são arquivos espelhados: TYPES descreve a forma na declaração, LITERAL descreve a sintaxe do valor.

Operadores

Descricao

Operadores aritméticos da linguagem TheFlux. Diferencia divisão decimal (/f), divisão inteira (/i) e resto de divisão (/r), assim como exponenciação (^e) e radiciação (^r). Os operadores seguem a precedência matemática padrão.

Sintaxe

<expr> + <expr>    # Adição
<expr> - <expr>    # Subtração
<expr> * <expr>    # Multiplicação
<expr> /f <expr>   # Divisão decimal (resultado "type">float)
<expr> /i <expr>   # Divisão inteira (resultado "type">int)
<expr> /r <expr>   # Resto da divisão (módulo)
<expr> ^e <expr>   # Exponenciação (potência)
<expr> ^r <expr>   # Radiciação (raiz)

Pseudocodigo

r := a + b - c * d /f e   // + - * /f /i /r ^e ^r

Usos

Operações básicas

Soma, subtração e multiplicação.

"kw">mut "kw">as "type">int64: soma= 2 + 3
"kw">mut "kw">as "type">int64: sub= 10 - 4
"kw">mut "kw">as "type">int64: mult= 6 * 7

Divisão especializada

Três formas de divisão para diferentes necessidades.

"kw">mut "kw">as "type">int64: div_int= 7 /i 2     # 3 (divisão inteira)
"kw">mut "kw">as "type">float64: div_dec= 7 /f 2   # 3.5 (divisão decimal)
"kw">mut "kw">as "type">int64: resto= 7 /r 2       # 1 (resto da divisão)

Exponenciação e radiciação como operadores infixos.

"kw">mut "kw">as "type">int64: pot= 2 ^e 3         # 8 (2³)
"kw">mut "kw">as "type">float64: raiz= 27 ^r 3     # 3.0 (raiz cúbica de 27)

Restricoes

  • /i requer operandos inteiros e retorna inteiro (truncado em direção a zero).
  • /f converte operandos para float antes da divisão.
  • /r é o operador de módulo (resto da divisão inteira).
  • ^e é exponenciação: base^e expoente.
  • ^r é radiciação: base^r indice_raiz (ex: 27^r3 = raiz cúbica).

Descricao

borrow
Keywords

Descricao

Empréstimo dos valores de um identificador sem transferir a sua posse (ownership). borrow() é imutável — múltiplos empréstimos simultâneos são permitidos. borrow_mut() é exclusivo — bloqueia outros borrows, moves e escritas por referência externa.

Sintaxe

"kw">borrow(<identificador>)
borrow_mut(<identificador>)

Pseudocodigo

x  ← 42
leitura := EMPRESTAR(x)      // emprestimo imutavel, compartilhado
outra   := EMPRESTAR(x)      // permitido: varias leituras simultaneas
escrita := EMPRESTAR_MUT(x)  // exclusivo: bloqueia outros emprestimos

Usos

Borrow imutável múltiplo

Múltiplos borrows imutáveis simultâneos são permitidos.

"kw">mut "kw">as "type">int64: x = 42
"kw">mut "kw">as "type">int64: r1 = "kw">borrow(x)
"kw">mut "kw">as "type">int64: r2 = "kw">borrow(x)
"kw">print(r1 + r2)

Borrow mutável exclusivo

borrow_mut() bloqueia outros borrows, moves e escritas externas.

"kw">mut "kw">as "type">int64: x = 42
"kw">mut "kw">as "type">int64: ref = borrow_mut(x)
ref = 100
"kw">print(ref)

Valor original preservado

Operações em referências não alteram o valor original.

"kw">mut "kw">as "type">int64: x = 42
"kw">mut "kw">as "type">int64: r = "kw">borrow(x)
"kw">print(r)
"kw">print(x)

Restricoes

  • borrow() imutável: múltiplos simultâneos OK.
  • borrow_mut() exclusivo: bloqueia outros borrows, moves e escritas.
  • Leitura de variável em borrow_mut por referência diferente → erro.
  • Reatribuição de ref via borrow_mut() é permitida.

Keywords

Descricao

Inibe a liberação automática do Eager Flow Disposal, estendendo o tempo de vida do dado. Sem keep(), o compilador determina o ponto de última uso de cada variável e a libera automaticamente. keep(x) mantém x válido até o final do bloco léxico.

Destino transparente que preserva o valor em pipeline.

"kw">mut "kw">as "type">int64: x = 42

Descricao

Keywords

Descricao

Modificador que transforma uma função em uma operação não-bloqueante que retorna um Future. A função marcada com async não bloqueia a pipeline síncrona que a invoca; seu corpo é avaliado sob demanda e o resultado é resolvido quando a pipeline consome o Future com await.

"kw">async "kw">function <nome_camelCase> (<parâmetros>) ["kw">as <tipo_retorno>] {
<instruções>
}

Função assíncrona que retorna Future

"kw">async "kw">function dobro ("kw">as "type">int64: n) "kw">as "type">int64 {
"kw">mut "kw">as "type">int64: res = n * 2
"kw">emit("kw">nice, res, "ok")
}
"kw">program (Main) {

}

await
Keywords

Descricao

Ponto de sincronização linear que suspende a pipeline síncrona até a resolução de um Future. Ao encontrar await, a esteira de execução bloqueia de forma determinística até que o Future associado (gerado por uma função async ou despachado por spawn) esteja resolvido, e então retorna o seu valor.

Sintaxe

"kw">await <expressão_future>

Usos

Await de Future de função async

Suspende a pipeline até o Future retornado pela função async resolver.

"kw">async "kw">function dobro ("kw">as "type">int64: n) "kw">as "type">int64 {
"kw">mut "kw">as "type">int64: res = n * 2
"kw">emit("kw">nice, res, "ok")
}
"kw">program (Main) {
"kw">print("kw">await dobro(21))   # 42
}

Await de Future despachado por spawn

Coleta o resultado de um nó do dataflow despachado como green thread.

"kw">mut g = "kw">spawn (dobro(20 + 1) --> "kw">print)
"kw">print("kw">await g)

Restricoes

  • Só pode ser aplicado a valores do tipo Future.
  • Aplicar await a um valor não-assíncrono é rejeitado pela análise semântica.
  • Suspende de forma linear e determinística a pipeline síncrona até a resolução do Future.

Keywords

Descricao

Gatilho de execução assíncrona: autoriza e despacha um nó ou o caminho do dataflow para o runtime, que o executa como uma green thread cooperativa. "kw">print("kw">await g)

Despacha um nó isolado do grafo de fluxo para execução assíncrona no runtime.

  • O spawn autoriza e despacha o nó ou caminho do dataflow para o runtime como green thread.

Descricao

Descricao

Caracteres ASCII e Unicode entre aspas simples.

Code points não-ASCII (1-4 bytes UTF-8) direto ou via escape.

Tipo multidimensional (matriz, vetor) com forma estática, armazenado em buffer plano (flat) na ordem row-major e indexado por strides. Deve ser declarado com as dimensões e o tipo dos elementos (ex.: tensor[2, 2] of int32).

Sintaxe

"kw">mut "kw">as "type">tensor[<dim1>, <dim2>, ...] "kw">of <tipo_elemento>: <var1>, ... [= <valores>]

Pseudocodigo

m : TENSOR[2, 3] DE "type">int32   // forma estatica, armazenamento row-major

Usos

Vetor unidimensional

Vetor com tipo de elemento explícito.

"kw">mut "kw">as "type">tensor[3] "kw">of "type">float32: t1 = [1.5, 2.5, 3.5]

Matriz bidimensional

Matriz com acesso multi-índice 1-based.

"kw">mut "kw">as "type">tensor[2, 2] "kw">of "type">int32: t2 = [
    [10, 20],
    [30, 40]
]
"kw">print(t2[2, 2])   # 40

Index-assign

Atribuição por multi-índice.

"kw">mut "kw">as "type">tensor[2, 2] "kw">of "type">int64: t = [[10, 20], [30, 40]]
t[2, 1] = 99
"kw">print(t)   # [[10, 20], [99, 40]]

Restricoes

  • O nome do tipo é minúsculo (tensor, não Tensor); sem forma capitalizada.
  • A forma deve ser totalmente estática (ex: [3, 4]); dimensões inteiras positivas.
  • O tipo do elemento deve ser um tipo numérico implementado.
  • Índices são 1-based em todas as dimensões na fonte; o backend traduz automaticamente para offset 0-based (índice literal vira constante de compilação; índice variável gera `sub 1`).
  • Layout runtime é buffer flat row-major com strides `S_último=8`, `S_k = d_{k+1} * S_{k+1}` bytes; elemento ocupa exatamente 8 bytes (float bitcast, string como FAT `(ptr<<32)|len`).
  • Header do bloco contém `[rank, d0..d{rank-1}]` para print genérico e debug.
  • Literal initializer deve ser retangular e compatível com a shape declarada (ragged/mismatch é erro em semantic e runtime).
  • A leitura preserva o tipo do elemento declarado (não força float64).
  • Write valida bounds de todas as dimensões percorridas.
  • Print/concat usam formato aninhado `[[10, 20], [99, 40]]`.

Sintaxe

Mapa (map)

Dicionário com chaves string e acesso dinâmico; ausente retorna none.

"kw">mut "kw">as "type">map: metricas = "type">map { "threads": 8, "batch": 32 }

"kw">print(metricas["ausente"])  # "type">none

Chaves string (.nome of string) ou numéricas (.1 of uint8 -> chave runtime "1"); anotação opcional de tipo no valor (of string, of bool, ...).

"kw">mut "kw">as "type">map: codigos = "type">map{.1 "kw">of "type">uint8: "Norte" "kw">of "type">string, .2 "kw">of "type">uint8: "Nordeste" "kw">of "type">string}
"kw">print(codigos["1"])  # Norte
"kw">print(codigos["5"])  # "type">none

Operações da stdlib

24 ops do agente MapStdLib (insertEntry, containsKey, merge, extractKeys, toMap, ...) via use MapStdLib.

"kw">use MapStdLib
"kw">mut "kw">as "type">map: m = "type">map{.name "kw">of "type">string: "flux"}
println(keys(m))          # [name]
println(merge(m, "type">map{.x "kw">of "type">string: 9}))  # {name: flux, x: 9}

Restricoes

  • Map aceita chaves novas por atribuição dinâmica.
  • Acesso a chave ausente em map retorna none (não causa erro).
  • Print usa {k: v, ...} (ordem de inserção, strings sem aspas); concat "texto: " + <map> usa a forma formatada.
  • Chave de entrada tipada: of string -> lexema; of uint8/int64/... numérico -> string do dígito; of <tipo> no valor é anotação (sem coerção em runtime).
  • Suportado nos 5 backends (in, vm, wat, wasm, llvm).

?
Keywords

Descricao

Bloco short-circuit que avalia uma expressão. O retorno dessa expressão é um struct transparente gerado e enviado internamente pelo comando `emit`. O operador `?` intercepta esse struct e despacha o fluxo para um dos dois braços obrigatórios: executa o primeiro braço quando o struct transparente possui `.sta == "fail"`, e o segundo braço quando `.sta == "nice"`. O struct retornado é ligado diretamente na variável resultante (permitindo ler `.sta`, `.val` e `.msg`) sem reavaliar a chamada.

Sintaxe

<expressão> ?
{
      ==> "kw">emit("kw">fail, variável, mensagem)   # `.sta` / `.val` / `.msg`
      ==> "kw">emit("kw">nice, variável, mensagem)   # `.sta` / `.val` / `.msg`
}

Pseudocodigo

resultado := avalia(expressao) ?   // struct de resultado transparente
estado    := resultado.estado      // leitura dos campos

Usos

Bloco short-circuit acessando os campos do resultado

Despacha para `fail` ou `nice` e le os campos .sta/.val/.msg do resultado.

"kw">function (validar) (idade: "type">int64) "kw">as "type">int64 {
      (idade > 18) ? {
            ==> "kw">emit("kw">fail, idade, "menor de idade") 
            ==> "kw">emit("kw">nice, idade, "maior de idade")
      }
}

"kw">imut "kw">as "type">int64: r = validar(15)
"kw">print(r.sta)     #L "">fail"
"kw">print(r.val)     #L 15
"kw">print(r.msg)     #L "menor de idade"

"kw">imut "kw">as "type">int64: r = validar(21)
"kw">print(r.sta)     #L "">nice"
"kw">print(r.val)     #L 21
"kw">print(r.msg)     #L "maior de idade"

Bloco atribuido: struct capturado na variavel

Quando o bloco short-circuit é atribuído a uma variável, o struct de resultado produzido pelo braço executado fica disponível nessa variável (.sta, .val e .msg), sem reavaliar a expressão original.

"kw">function (validar) (idade: "type">int64) "kw">as "type">int64 {
      (idade > 18) ? {
            ==> "kw">emit("kw">fail, idade, "menor de idade")
            ==> "kw">emit("kw">nice, idade, "maior de idade")
      }
}

"kw">imut "kw">as "type">int64: entrada = 15
"kw">imut "kw">as "type">int64: r = validar(entrada) ? {
      ==> "kw">emit("kw">fail, entrada, "erro na validacao")
      ==> "kw">emit("kw">nice, entrada, "validacao ok")
}
"kw">print(r)

Restricoes

  • O braço `fail` deve vir antes do braço `nice`.
  • Ambos os braços (`fail` e `nice`) são obrigatórios no bloco sintático do operador `?`.
  • A variável associada ao struct carrega os campos inteiros do resultado (`.sta`, `.val`, `.msg`). Quando injetada internamente por braços anônimos, seu escopo é restrito ao corpo do braço; quando declarada via atribuição externa, segue as regras normais de escopo da variável atribuída.
  • O bloco `?` é uma instrução válida dentro de blocos de função e operações.
