function
Keywords

Description

Declara uma function nomeada e reutilizável com parameters tipados e return optional (via `as <type_return>`). Parâmetros são immutable (`imut`) por pattern quando o modificador de mutabilidade for omitido (ex: `as <type>: <identifier>`); para permitir reassignment ao parameter no scope local, declare-o explicitamente como `mut as <type>: <identifier>`. Se o field de return não for explicitado no chamador, o field pattern de evaluatesção é o `.val`. Functions são declaradas no topo do file (.flux) ou no body de agents/impl (.fdsl), antes do `program`, e can be chamadas por `nome(args)`; o resultado integer fica disponível via variable (`r = calc(5)`) e cada field é lido com acesso nomeado.

O verificador semântico checa que todas as ops do contract estão implementadas com aridade e types corretos.

Restrictions

  • O nome do agent deve estar em PascalCase.
  • Nomes de contracts repetidos no mesmo impl são error semântico.
  • Cada operation de cada contract must be implementada com aridade e types correspondentes.
  • Agents podem ter ops adicionais além das exigidas pelo contract (ops extras são permitidas).
  • A cláusula `impl` cannot be used em files .flux (apenas .fdsl).

Keywords

Description

Declara um agent em files .fdsl. Agents são unidades modulares que encapsulam operations (op). O nome do agent deve estar em PascalCase. Agents são proibidos em files .flux.

            <instruções>
            "kw">emit("kw">nice | "kw">fail, <identifier>, "<mensagem>")
      }
      ...
}

Pseudocode

    OPERACAO acelerar(velocidade):
        ...
// unidade modular que encapsula operations ("kw">op)

Usages

Agent simples

Agent que declara operations sem parameters.

"kw">agent (AgentOfMath) {

            "kw">print("Produto Escalar")

      "kw">op crux ==> {
            "kw">print("Produto Vetorial")
      }
}

Agent com ops que receive parameters nomeados ([mut | imut | as] <type>: <id>), return optional ([as <type>]) e block com ==>.

"kw">agent (AgentOfMath) {
      "kw">op dot ("kw">as "type">int64: x, "kw">as "type">int64: y) "kw">as "type">int64 ==> {
            "kw">mut "kw">as "type">int64: res = x + y
            "kw">emit("kw">nice, res, "ok")

            "kw">emit("kw">nice, nome, "ok")
      }

Agent que encapsula estado com declarations mut/imut.

"kw">agent (AgenteContador) {
      "kw">mut "kw">as "type">int64: total = 0

            total =+ passo
            "kw">emit("kw">nice, total, "ok")

}

  • O nome do agent deve estar em PascalCase.
  • Um agent pode implementar no máximo um contract usando a cláusula `impl`.
  • Operations (`op`) declaradas no body do agent seguem a sintaxe `op nomeCamelCase ([mut | imut | as] <type>: <id> ...) [as <type>] ==> { <body> }`.

  • O body de um agent é delimitado por braces `{}` e pode conter variables, functions e operations.
  • Agents can be importados em files `.flux` através da declaration `use`.

match
Keywords

Description

Realiza casamento de patterns (pattern matching) sobre uma expression. O match é uma expression e returns o value producesido pelo primeiro branch cujo pattern corresponda ao value analisado e cuja guard (guard), quando presente, seja verdadeira. A sintaxe de desestruturação reutiliza exatamente a mesma forma utilizada na construção de structs e variants de enum, tornando construção e desconstrução operations simétricas. Para enums, o compilador verifica exaustividade e detecta branches inalcançáveis.

Syntax

"kw">match (<expression>) {

    <pattern> ==> <expression>

    <pattern> (<expressao_booleana>)
        ==> <expression>

    ...

}

Pseudocode

ESCOLHER(expressao):
    CASE padrao_1: resultado_1
    CASE padrao_2: resultado_2
    PADRAO: resultado_fallback

Usages

Match with literals

Seleciona um branch com base em values literais.

"kw">match (valor) {

    1 ==> "um"

    2 ==> "dois"

    _ ==> "outro"

}

Match with enum

Desestrutura variants de enum utilizando a mesma sintaxe empregada durante sua construção.

"kw">match (resposta) {

    Resultado::Ok(
        .valor: valor
    ) ==> valor

    Resultado::Erro(
        .mensagem: mensagem
    ) ==> mensagem

}

Match with struct

Desestrutura structs utilizando exatamente a mesma sintaxe utilizada durante sua construção.

"kw">match (evento) {

    Evento(

        .nome: nome

        .quando: quando

        .contador: contador

    ) ==> contador

}

Match with record

Desestrutura registros anônimos por nome de field.

"kw">match (registro) {

    {

        .tipo: "sensor"

        .valor: valor

    } ==> valor

    {

        .tipo: tipo

    } ==> tipo

    _ ==> "desconhecido"

}

Match with guard

Executes o branch apenas quando o pattern corresponde e a condition booleana é verdadeira.

"kw">match (resultado) {

    Resultado::Ok(
        .valor: valor
    ) (valor >= 0) ==> "positivo"

    Resultado::Ok(
        .valor: valor
    ) ==> "negativo"

    Resultado::Erro(
        .mensagem: msg
    ) ==> msg

}

Nested match

Permite desestruturar estruturas compostas em um único pattern.

"kw">match (usuario) {

    Usuario::Ativo(

        .pessoa:

            Pessoa(

                .nome: nome

                .idade: idade

            )

    ) ==> nome

    Usuario::Bloqueado(

        .motivo: motivo

    ) ==> motivo

}

Restrictions

  • Match é uma expression.
  • O match returns o value producesido pelo primeiro branch correspondente.
  • Deve existir pelo menos um branch.
  • Os branches são evaluatesdos na ordem em que aparecem.
  • O primeiro pattern correspondente cuja guard seja verdadeira encerra a evaluatesção.
  • A guard é optional e é escrita como expression booleana entre parentheses após o pattern.
  • A guard não é um pattern: um branch precisa de um pattern (branches somente com guard são error de parse).
  • Guards são evaluatesdos somente após o pattern correspondente ser satisfeito.
  • Um branch com guard não cobre incondicionalmente o pattern: variants/wildcards guarddos não tornam o match exaustivo nem marcam branches seguintes como inalcançáveis.
  • O pattern _ corresponde a qualquer value.
  • Todo field é obrigatoriamente prefixado por dot (.) e ocupa uma linha própria; fields são separados por quebra de linha (EOL), nunca por comma.
  • Patterns de struct verificam nominalmente o type.
  • Patterns de enum verificam nominalmente o enum e a variant.
  • A correspondência dos fields ocorre pelo nome, nunca pela posição.
  • Fields can be ignorados utilizando _.
  • A construção e a desestruturação utilizam exatamente a mesma estrutura sintática.
  • Em backends tipados (LLVM, WASM/WAT), todos os branches devem producesir types compatíveis.
  • Quando a expression analisada possuir um type enum, o compilador deve verificar a exaustividade do match.
  • Um match é considerado exaustivo quando todas as variants do enum são cobertas explicitamente ou quando existe um branch wildcard (_).
  • Para structs, o pattern matching é naturalmente exaustivo, pois existe apenas um construtor possível.
  • O compilador deve detectar branches inalcançáveis.
  • Um branch cujo pattern nunca possa ser selecionado constitui error semântico.
  • Patterns de listas ainda não são suportados; o parser deve emitir PAR001.
_
Keywords

Description

O character underscore (`_`) atua como curinga (wildcard) universal e pattern de descarte na linguagem TheFlux. É utilizado como branch catch-all em estruturas `route`, como pattern universal em expressions `match` (garantindo exaustividade em enums e types literais), e como descarte de fields na desestruturação de structs, registros e variants de enums.

Syntax

"kw">route {
      <condition> ==> { <bloco> }
      _          ==> { <"kw">fallback> }
}
"kw">match (<expression>) {
      <pattern> ==> <expressão_ou_bloco>
      _        ==> <"kw">fallback>
}
{ .campo1: <pattern>, .campo2: _ }

Pseudocode

ESCOLHER(estado):
    CASE 0: pronto()
    PADRAO(_): ignora_qualquer_outro()   // curinga universal

Usages

Branch catch-all em route

Captura qualquer condition não atendida pelos branches anteriores em um block route.

"kw">route {
      status == "ativo"    ==> { "kw">print("Conexao ativa") }
      status == "bloqueio" ==> { "kw">print("Acesso bloqueado") }
      _                    ==> { "kw">print("Status desconhecido") }
}

Pattern wildcard universal em match

Corresponde a qualquer value não coberto anteriormente, garantindo exaustividade.

"kw">match (codigo) {
      200 ==> "kw">print("Sucesso")
      404 ==> "kw">print("Nao encontrado")
      _   ==> "kw">print("Outro codigo: padrao curinga")
}

Descarte de fields em desestruturação

Permite ignorar fields específicos durante o pattern matching de estruturas ou registros.

"kw">match (evento) {
      { .tipo: "sensor", .leitura: val } ==> "kw">print("Leitura: " + val)
      { .tipo: "alerta", .leitura: _ }   ==> "kw">print("Alerta sem telemetria")
      _                                  ==> "kw">print("Evento ignorado")
}

Restrictions

  • Em estruturas route, o branch wildcard `_` must be obrigatoriamente o último branch quando presente.
  • Em expressions match, o pattern wildcard `_` sem guard (guard) captura qualquer value e encerra a exaustividade.
  • Branches posicionados após um `_` incondicional generate errorr semântico de código inalcançável.
  • Can be utilizado para ignorar fields individuais em patterns de struct, enum ou registros anônimos.

emit
Keywords

Description

Encerra a function atual devolvendo um struct implícito de resultado com três fields sempre definidos: `.sta` ("nice" | "fail"), `.val` (value do identifier emitido, tipado pelo `as <type>` da function) e `.msg` (mensagem string ou interpolada). `emit` é o statement terminal required do body de uma function. O struct integer fica disponível via variable (`r = calc(5)`); depois leia cada field com acesso nomeado.

Syntax

"kw">emit("kw">nice, <identifier>, "<mensagem>")
"kw">emit("kw">fail, <identifier>, "<mensagem>")

Pseudocode

FUNCAO calc(x):
    IF invalido(x):
        EMITIR(falha, x, "entrada invalida")
    EMITIR(ok, x * 2, "calculado")   // terminal: encerra a "kw">function

Usages

Emit nice com return e consumo dos fields

Devolve o resultado de success; o chamador lê .sta, .val e .msg.

"kw">function (calc) (x: "type">int64) "kw">as "type">int64 {
      "kw">emit("kw">nice, x, "ok")
}

"kw">program (Main) {
      "kw">imut "kw">as "type">int64: r = calc(5)
      "kw">print(r.sta)     # "">nice"
      "kw">print(r.val)     # 5
      "kw">print(r.msg)     # "ok"
}

Emit fail em caminho de error

Devolve status de error em um branch de route; os três fields continuam preenchidos.

"kw">function (dividir) (dividendo: "type">int64, divisor: "type">int64) "kw">as "type">int64 {
      "kw">route {
            divisor == 0 ==> {
                  "kw">emit("kw">fail, divisor, "divisao por zero")
            }
            _ ==> {
                  "kw">mut "kw">as "type">int64: resultado = dividendo /i divisor
                  "kw">emit("kw">nice, resultado, "divisao executada")
            }
      }
}

Devolve o status de error junto com o value e a mensagem.

"kw">function (validar) (idade: "type">int64) "kw">as "type">int64 {
      "kw">route {
            idade < 18 ==> {
                  "kw">emit("kw">fail, idade, "menor de idade")
            }
            _ ==> {
                  "kw">emit("kw">nice, idade, "validacao concluida")
            }
      }
}

"kw">print(r.sta)     # "">fail"
"kw">print(r.val)     # 15
"kw">print(r.msg)     # "menor de idade"

  • Apenas os status `nice` (success) e `fail` (error) são permitidos.
  • `emit` é o statement terminal do body de uma function — nada pode vir depois.
  • `value` é um único identifier declarado (sem lista, sem expression).

  • Functions com `as <type>` de return devem ter `emit` em todo caminho de execução (loops não contam).

Keywords

Description

"kw">emit("kw">fail, <identifier>, "<mensagem>")

Emit fail em caminho de error

      "kw">route {

                  "kw">emit("kw">nice, idade, "validacao concluida")

}

  • `fail` só can be used como status do primeiro argument de `emit()` e como branch `==> emit(fail, ...)` do operator `?` (o branch fail vem antes do branch nice).

  • A mensagem é required e must be string literal ou interpolada.
  • Divisão por zero gera o status `fail` automaticamente, com mensagem 'divisao por zero'.

..
Operators

Description

O operator .. (range) tem dois usages: cria intervals numéricos inclusivos para iteration em infinite (a .. b), e especifica slices (slices) em coleções e strings [start .. end] ou (start .. end). O range é inclusivo em ambas as extremidades. Veja também KW_slices.yaml para o guia completo de slices.

Syntax

<início> .. <fim>                     # Range numérico para iteração
[<início> .. <fim>]                   # Slice em "type">list/"type">data/"type">tensor
[.. <fim>]                            # Slice do início até <fim>
[<início> ..]                         # Slice de <início> até o final
[..]                                  # Slice completo (cópia superficial)
(<início> .. <fim>)                   # Slice em "type">string (após identificador)
(..<fim>)                             # Slice de "type">string do início até <fim>
(<início> ..)                         # Slice de "type">string de <início> até o final
(..)                                  # Slice de "type">string completo

Pseudocode

intervalo := 1 .. 10   // range numerico inclusivo

Usages

Range para iteration

Itera sobre um interval numérico inclusivo.

"kw">infinite (i "kw">in 1 .. 5) {
    "kw">print(i)  # 1, 2, 3, 4, 5
}
"kw">infinite (i "kw">in -4 .. 4) {
    "kw">print(i)  # -4, -3, -2, -1, 0, 1, 2, 3, 4
}

Slice de lista

Extrai uma slice de uma lista.

"kw">mut "kw">as "type">list: valores= [10, 20, 30, 40, 50]
"kw">print(valores[..])       # [10, 20, 30, 40, 50]
"kw">print(valores[..3])      # [10, 20, 30]
"kw">print(valores[2..])      # [30, 40, 50]
"kw">print(valores[2..4])     # [30, 40]

Slice de string

Extrai uma substring usando parentheses após o identifier.

"kw">mut "kw">as "type">string: texto= "flux"
"kw">print(texto(..))      # flux
"kw">print(texto(2..3))    # lu

Restrictions

  • O range a..b é inclusivo em ambas as extremidades.
  • Range descendente (a > b) é permitido e itera do maior ao menor.
  • Indexs em list/string são 1-based e o fim do slice é inclusivo.
  • Set/map não suportam slice.
  • Slice com passo só é suportado em tensor; em list/string generates errorr.
  • A sintaxe de slice de string usa parentheses (texto(2..3)); brackets em string não são suportados.
  • .. em route with subject é um wildcard (sempre True).
slices
Operators

Description

Slices extraem slices de coleções e strings usando o operator de range .. dentro de delimitadores. O delimitador depende do type: brackets [ ] para list, data e tensor; parentheses ( ) para string. O range é inclusivo em ambas as extremidades e os indexs são 1-based.

Syntax

lista[ .. ]              # Slice completo (cópia)
lista[x .. ]             # De x até o final
lista[ .. y]             # Do início até y
lista[x .. y]            # De x até y (inclusivo)
texto( .. )              # String completa (cópia)
texto(x .. )             # Substring de x até o final
texto( .. y)             # Substring do início até y
texto(x .. y)            # Substring de x até y (inclusivo)

Pseudocode

numeros := [1, 2, 3, 4, 5]
fatia   := numeros[2..4]   // extrai subcolecao

Usages

Slice de lista

Extrai uma slice de uma list com brackets.

"kw">mut "kw">as "type">list "kw">of "type">int64: valores = [10, 20, 30, 40, 50]
"kw">print(valores[ .. ])     # [10, 20, 30, 40, 50]
"kw">print(valores[ .. 3])    # [10, 20, 30]
"kw">print(valores[2 .. ])    # [20, 30, 40, 50]
"kw">print(valores[2 .. 4])   # [20, 30, 40]

Slice de tensor

Slice a primeira dimension de um tensor com brackets; passo é suportado apenas em tensor.

"kw">mut "kw">as "type">tensor[4] "kw">of "type">int64: t = "type">tensor([1, 2, 3, 4])
"kw">print(t[2 .. 4])         # [2, 3, 4]
"kw">print(t[1 .. 4 .. 2])    # [1, 3]

Slice de data

Slice uma lista de data (registros) com brackets.

"kw">mut "kw">as "type">list "kw">of "type">data: itens = [{a: 1}, {a: 2}, {a: 3}]
"kw">print(itens[2 .. 3])     # [{a: 2}, {a: 3}]

Slice de string

Extrai uma substring com parentheses; indexs contam codepoints Unicode.

"kw">mut "kw">as "type">string: texto = "flux"
"kw">print(texto( .. ))       # flux
"kw">print(texto( .. 3))      # flu
"kw">print(texto(2 .. ))      # lux
"kw">print(texto(2 .. 3))     # lu

  • Indexs são 1-based e o fim é inclusivo.
  • Início, fim ou ambos can be omitidos; omitidos assumem o início/fim da coleção.
  • Fora do interval válido (1..size) ou início maior que fim generates errorr at runtime.
  • Passo (sintaxe `[início .. fim .. passo]`) só é suportado em tensor; em list e string generates errorr.
  • Set e map não suportam slice.
  • O delimitador segue o type: [ ] para list/data/tensor, ( ) para string.

Keywords

Description

Description

Description

., ::, [], ..
Operators

Description

Operators fundamentais para acesso a membros, resolução de scope, indexação e slicemento em TheFlux:
- `.` (dot): Field access de instâncias de `struct` e `data`, propriedades de return de operations (`res.sta`, `res.val`, `res.msg`) e chamadas de métodos.
- `::` (colon duplo): Resolução estática de scope para variants de enum (`Enum::Variant`), operations de agents (`Agent::operation`) e símbolos de modules.
- `[ ]` (brackets): Acesso por index posicional em `list` (1-based), acesso associativo por chave em `map` (`mapa["chave"]`), e acesso multidimensional em `tensor` (`tensor[i, j]`).
- `..` (range/slice): Fatiamento contíguo dentro de brackets (`[ini..fim]`, `[..fim]`, `[ini..]`, `[..]`) para listas, strings e tensores, além de iteration em ranges.

Syntax

<expr>.<field>                      # Acesso a campo de struct ou "type">data
<expr>.<propriedade>                # Acesso a propriedades de retorno (sta, val, msg)
<"kw">Enum>::<Variante>                  # Acesso a variante de enumeração
<Agente>::<operacao>()              # Acesso e invocação de operação de agente
<Modulo>::<simbolo>                 # Acesso a símbolo de namespace importado
<lista>[<indice>]                   # Acesso posicional a elemento de lista
<mapa>[<chave>]                     # Acesso associativo por chave em mapa
<"type">tensor>[<dim1>, <dim2>]            # Acesso multidimensional a elemento de "type">tensor
<colecao>[<inicio> .. <fim>]        # Fatiamento (slice) por faixa de índices

Pseudocode

obj.campo          // acesso a field (.)
Modulo::item       // resolucao de scope (::)
colecao[1]         // indexacao ([]) — 1-based
fatia := colecao[2..5]   // slice (range)

Usages

Field access e propriedades (.)

Acessa fields em structs, objetos data e propriedades de return de operations.

      "kw">mut: .x: "type">float64
      "kw">mut: .y: "type">float64
}

"kw">program (ExemploPonto) {
      "kw">mut "kw">as Ponto: p = Ponto(
            .x: 10.5
            .y: 20.0
      )
      "kw">print(p.x)
      p.y = 35.0
}
"kw">mut "kw">as "type">data: payload = "type">data(.nome: "TheFlux", .ativo: "kw">true)
"kw">print(payload.nome)
payload.status = "online"

Resolução de scope e namespaces (::)

Acessa variants de enum, operations de agents e símbolos de modules importados.

enum (Status) {
      Ativo
      Inativo
}

"kw">program (ExemploEnum) {
      "kw">mut "kw">as Status: s = Status::Ativo
      "kw">print(s)
}
"kw">use AgentOfPrint "kw">as AP

"kw">program (ExemploAgente) {
      AP::printNome()
}

Indexação e slicemento ([ ] e ..)

Acessa elementos em listas, mapas, tensores e extrai slices de coleções.

"kw">mut "kw">as "type">list "kw">of "type">int64: valores = [10, 20, 30, 40, 50]
"kw">print(valores[1])      # Primeiro elemento (10)
"kw">print(valores[2..4])   # Sublista [20, 30, 40]
"kw">print(valores[..3])    # Do inicio ate o 3o [10, 20, 30]
"kw">print(valores[3..])    # Do 3o ate o final [30, 40, 50]
"kw">mut "kw">as "type">tensor[2, 2] "kw">of "type">float64: matriz

"kw">mut "kw">as "type">float64: elem = matriz[1, 2]

Restrictions

  • O dot (.) é utilizado para fields de struct, data e propriedades de return. Mapas não aceitam .field (requerem mapa["chave"]).
  • O operator :: é estático e reservado para Enum::Variant, Agent::operation e Module::simbolo.

  • O operator de range .. em [a..b] é inclusivo em ambas as extremidades e preserva o type da coleção original.
  • Is not allowed aplicar slicemento (..) diretamente sobre types set ou map.
?
Keywords

Description

Block short-circuit que evaluates uma expression. O return dessa expression é um struct transparente gerado e enviado internamente pelo comando `emit`. O operator `?` intercepta esse struct e despacha o fluxo para um dos dois branches requireds: executes o primeiro branch quando o struct transparente possui `.sta == "fail"`, e o segundo branch quando `.sta == "nice"`. O struct returnsdo é ligado diretamente na variable resultante (permitindo ler `.sta`, `.val` e `.msg`) sem reevaluatesr a chamada.

Syntax

<expression> ?
{
      ==> "kw">emit("kw">fail, variável, mensagem)   # `.sta` / `.val` / `.msg`
      ==> "kw">emit("kw">nice, variável, mensagem)   # `.sta` / `.val` / `.msg`
}

Pseudocode

resultado := avalia(expressao) ?   // struct de resultado transparente
estado    := resultado.estado      // leitura dos fields

Usages

Block short-circuit acessando os fields do resultado

Despacha para `fail` ou `nice` e le os fields .sta/.val/.msg do resultado.

"kw">function (validar) (idade: "type">int64) "kw">as "type">int64 {
      (idade > 18) ? {
            ==> "kw">emit("kw">fail, idade, "menor de idade") 
            ==> "kw">emit("kw">nice, idade, "maior de idade")
      }
}

"kw">imut "kw">as "type">int64: r = validar(15)
"kw">print(r.sta)     #L "">fail"
"kw">print(r.val)     #L 15
"kw">print(r.msg)     #L "menor de idade"

"kw">imut "kw">as "type">int64: r = validar(21)
"kw">print(r.sta)     #L "">nice"
"kw">print(r.val)     #L 21
"kw">print(r.msg)     #L "maior de idade"

Block atribuido: struct capturado na variable

Quando o block short-circuit é atribuído a uma variable, o struct de resultado producesido pelo branch executesdo fica disponível nessa variable (.sta, .val e .msg), sem reevaluatesr a expression original.

"kw">function (validar) (idade: "type">int64) "kw">as "type">int64 {
      (idade > 18) ? {
            ==> "kw">emit("kw">fail, idade, "menor de idade")
            ==> "kw">emit("kw">nice, idade, "maior de idade")
      }
}

"kw">imut "kw">as "type">int64: entrada = 15
"kw">imut "kw">as "type">int64: r = validar(entrada) ? {
      ==> "kw">emit("kw">fail, entrada, "erro na validacao")
      ==> "kw">emit("kw">nice, entrada, "validacao ok")
}
"kw">print(r)

Restrictions

  • O branch `fail` deve vir antes do branch `nice`.
  • Ambos os branches (`fail` e `nice`) são requireds no block sintático do operator `?`.
  • A variable associada ao struct carrega os fields integers do resultado (`.sta`, `.val`, `.msg`). Quando injetada internamente por branches anônimos, seu scope é restrito ao body do branch; quando declarada via assignment externa, segue as regras normais de scope da variable atribuída.
  • O block `?` é uma instrução válida dentro de blocks de function e operations.

Function assíncrona que returns Future

"kw">async "kw">function dobro ("kw">as "type">int64: n) "kw">as "type">int64 {

await
Keywords

Description

Linear synchronization point that suspends the synchronous pipeline until a Future resolves. Ao encontrar await, a esteira de execução bloqueia de forma determinística até que o Future associado (gerado por uma function async ou despachado por spawn) esteja resolvido, e então returns o seu value.

Syntax

"kw">await <expressão_future>

Usages

Await de Future de function async

Suspende a pipeline até o Future returnsdo pela function async resolver.

"kw">async "kw">function dobro ("kw">as "type">int64: n) "kw">as "type">int64 {
"kw">mut "kw">as "type">int64: res = n * 2
"kw">emit("kw">nice, res, "ok")
}
"kw">program (Main) {
"kw">print("kw">await dobro(21))   # 42
}

Await de Future despachado por spawn

Coleta o resultado de um nó do dataflow despachado como green thread.

"kw">mut g = "kw">spawn (dobro(20 + 1) --> "kw">print)
"kw">print("kw">await g)

Restrictions

  • Só can be aplicado a values do type Future.
  • Aplicar await a um value não-assíncrono é rejeitado pela análise semântica.
  • Suspende de forma linear e determinística a pipeline síncrona até a resolução do Future.

Keywords

Description

Gatilho de execução assíncrona: autoriza e despacha um nó ou o caminho do dataflow para o runtime, que o executes como uma green thread cooperativa. Diferente de async (que apenas marca a function como não-bloqueante), o spawn já inicia a execução no runtime, e o await coleta o resultado posteriormente.

Syntax

"kw">spawn <expression>

Usages

Autoriza e despacha um caminho do dataflow como green thread; o resultado é coletado com await.

Despacha um nó isolado do grafo de fluxo para execução assíncrona no runtime.

  • O spawn autoriza e despacha o nó ou caminho do dataflow para o runtime como green thread.
  • A execução ocorre de forma cooperativa e não-bloqueante; o resultado é coletado com await.
