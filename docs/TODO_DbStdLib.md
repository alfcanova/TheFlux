Para a DbStdLib, o design da biblioteca padrão de persistência e banco de dados na TheFlux deve atuar como um conector reativo entre a memória contígua da StructStdLib e um motor de armazenamento confiável de baixo nível (como um banco chave-valor ultra-rápido ou um motor relacional embutido do tipo SQLite).Como a TheFlux opera baseada em fluxo de dados lineares e contratos, a DbStdLib ganha um superpoder exclusivo: os contratos barram dados malformados na fronteira do pipeline, garantindo que o programa nunca tente gravar registros inválidos em disco, protegendo a integridade física do banco de dados antes mesmo de abrir uma transação.🎯 1. Funções Necessárias / EssenciaisAs funções de núcleo para inicialização, transações e operações fundamentais de escrita e leitura de registros estruturados (CRUD).dbOpen (as string: connection_string) as data (retorna um tipo db_connection)Objetivo: Abre uma conexão com o banco de dados embutido ou local em disco, inicializando os buffers de cache e estruturas de travamento de arquivo.dbExecute (as data: connection, as string: query, as list of data: params) as boolObjetivo: Executa comandos de mutação (como INSERT, UPDATE, DELETE ou criação de tabelas) de forma parametrizada para blindar o sistema contra ataques de injeção de código (SQL Injection).dbQuery (as data: connection, as string: query, as list of data: params) as list of dataObjetivo: Executa buscas de dados (SELECT) e retorna o resultado estruturado em uma lista nativa de mapas ou estruturas tipadas pela sua StructStdLib.dbTransactionBegin (as data: connection) as bool / dbTransactionCommit (as data: connection) as bool / dbTransactionRollback (as data: connection) as boolObjetivo: Controla o ciclo de vida de transações atômicas (ACID). Se qualquer passo na esteira linear falhar após o início, o runtime invoca o Rollback automaticamente para desfazer as alterações e manter a consistência.🧩 2. Funções AcessóriasFunções de conveniência focadas em metadados de tabelas, contagem de registros e blindagem por contratos.dbTableExists (as data: connection, as string: table_name) as boolObjetivo: Verifica se uma tabela específica já existe na estrutura do banco.dbLastInsertId (as data: connection) as int64Objetivo: Retorna o identificador numérico único (ID auto-incremental) gerado pela última inserção bem-sucedida de hardware.dbIsValidRecord (as data: connection, as string: table_name, as map: record) as boolObjetivo: Compara o mapa de dados com o esquema físico e as restrições (ex: chaves primárias, campos não-nulos) da tabela. Sugestão de Implementação no Cenário MultiendPersistir dados de forma portável exige mapear o motor de armazenamento de acordo com as restrições físicas de segurança e acesso de cada backend:A. No Interpretador (Python)Muito direto e rápido para fazer seus testes canônicos passarem. O seu interpretador em Python intercepta a chamada de dbOpen e delega as operações para o módulo nativo sqlite3 (banco relacional embutido em arquivo único do Python) ou cria um mapa persistido em disco usando o módulo shelve para uma abordagem puramente chave-valor.B. Na LLVM IR + Clang (.exe nativo)O seu compilador em Python atuará injetando vinculações estáticas com bibliotecas consagradas de arquivo único escritas em C.A Estratégia: O seu gerador de código Python adicionará as assinaturas externas de ligação para embutir o código do SQLite (a biblioteca sqlite3.c) diretamente dentro do binário .exe gerado pelo Clang. O executável final lida com arquivos locais no disco do usuário de forma extremamente rápida, aproveitando a LowLevelStdLib para gerenciar a paginação de memória de forma contígua.C. No WebAssembly (wasm / wat)No navegador, por questões de segurança (Sandbox), o WASM não tem permissão para abrir arquivos arbitrários ou criar bancos SQLite tradicionais diretamente no HD da máquina.A Solução para Web: O seu compilador Python gerará instruções em WAT declarando JS Bindings (importações externas). Quando o WASM invocar dbOpen, ele fará a ponte para que o JavaScript da página web inicialize e manipule o banco de dados nativo do navegador conhecido como IndexedDB ou faça o mapeamento na memória do localStorage. O trânsito de dados estruturados usará os buffers lineares de bytes do WASM de alta velocidade.D. O Casamento Rígido com Ownership e Async (move / borrow / async)Esta biblioteca brilha intensamente ao cruzar dados com as palavras-chave avançadas da linguagem:A abertura de conexões e checagens de validação (dbTableExists, dbIsValidRecord) usam estritamente a semântica de borrow. Elas apenas consultam os cabeçalhos sem travar ou consumir o canal de conexão do fluxo.As operações de gravação e transações consomem a instância do registro como um move. Uma vez que os dados do usuário são enviados para o nó de escrita do banco, o compilador Python apaga as referências da CPU na AST antiga para garantir que ninguém altere aquele dado contíguo de memória enquanto ele está sendo serializado no disco, disparando o resultado persistido pelo canal emit(nice, true, "ok").Como operações de disco e escrita física são intrinsecamente lentas em relação ao clock do processador, o agente da DbStdLib deve ser exposto de forma não-bloqueante usando o seu par async / wait, liberando a esteira linear para processar outros eventos paralelos enquanto os dados são gravados em background na LLVM ou no IndexedDB.
